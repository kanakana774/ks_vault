# Git/GitHub 説明用

## 1. 導入：Git/GitHubって何？（5分）

**要点：Gitは「セーブデータ管理」、GitHubは「セーブデータの共有サイト」**

*   **Gitとは：**
    *   ファイルの「変更履歴」を記録する道具。
    *   **ゲームのセーブポイント**のようなもの。「昨日の状態に戻したい！」が簡単にできる。
*   **GitHubとは：**
    *   Gitで作った記録をネット上に保存・公開する場所。
    *   **「DropboxやGoogleドライブのエンジニア特化版」**。チームで作業するためのSNSのような側面もある。


---

## 2. 概念図：3つの場所（3分）

**要点：「自分のPC（ローカル）」と「みんなの場所（リモート）」がある**

1.  **ワークツリー：** 今まさに作業している机（ファイル）。
2.  **ローカルリポジトリ：** 自分のPCの中にある「自分専用の保管庫」。
3.  **リモートリポジトリ（GitHub）：** ネット上にある「みんなの共有保管庫」。

---

## 3. 実践：cloneからpushまで（15〜20分）

ここからは、実際に手を動かす際の手順と、その時にかける言葉です。

### ① 準備：リポジトリを自分のPCに持ってくる (`clone`)
*   **説明：** 「まずは、ネット上（GitHub）にあるプロジェクトを自分のPCに丸ごとコピーしましょう。」
*   **コマンド：**
    ```bash
    git clone <URL>
    cd <ディレクトリ名>
    ```

### ② 自分の作業場を作る (`branch`)
*   **説明：** 「本番のコードを直接いじると怖いので、自分専用の**『作業用コピー（枝分かれ）』**を作ります。これを『ブランチを切る』と言います。」
*   **コマンド：**
    ```bash
    git checkout -b feature-my-work
    # (解説：-bは「新しく作る」という意味)
    ```

### ③ ファイルを編集する
*   **説明：** 「ここはいつも通り、VSCodeなどでファイルを書き換えて保存してください。」

### ④ 変更を記録する準備 (`add`)
*   **説明：** 「変更したファイルを、次の『セーブ（記録）』の対象に含める作業です。**『配送用の段ボールに荷物を詰める』**イメージです。」
*   **コマンド：**
    ```bash
    git add <ファイル名>  # または git add . (全部)
    ```

### ⑤ 変更を確定する (`commit`)
*   **説明：** 「段ボールにガムテープを貼って、**『何を変えたか』というメッセージを添えて**保管庫に入れます。これが自分の中での正式な記録になります。」
*   **コマンド：**
    ```bash
    git commit -m "〇〇の機能を修正"
    ```

### ⑥ GitHubに送る (`push`)
*   **説明：** 「自分のPCの中だけに記録しても、チームメンバーには見えません。最後に、**GitHub（ネット上の保管庫）へアップロード**します。」
*   **コマンド：**
    ```bash
    git push origin feature-my-work
    ```

---

## 4. 仕上げ：GitHubで確認（2分）

*   GitHubの画面を開き、自分の送ったブランチができていることを確認する。
*   「これであなたの作業が世界（またはチーム）に共有されました！」と締める。
*   （余裕があれば）「この後、リーダーに『確認してください』と送るのが**Pull Request（プルリク）**です」と一言添える。



---

## 教える時の注意

1.  **用語を恐れさせない**
    *   `clone` ＝ ダウンロード（履歴付き）
    *   `commit` ＝ メッセージ付きの保存
    *   `push` ＝ アップロード
    *   このように言い換える。

2.  **「add」と「commit」の違いを強調する**
    *   初心者は「なぜ2回もコマンド打つの？」と混乱しがち。
    *   「addは**『どの変更を保存するか選ぶ作業』**、commitは**『実際に保存する作業』**」と伝える。
