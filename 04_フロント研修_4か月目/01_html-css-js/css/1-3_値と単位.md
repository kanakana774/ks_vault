「値と単位」は、CSSでサイズや距離を指定するための「物差し」です。
現代のWeb制作では、iPhoneから4Kモニターまであらゆる画面サイズに対応する必要があるため、**「固定のpx（ピクセル）」に頼りすぎず、状況に応じて単位を使い分けること**が設計の肝になります。

初心者の方がまず覚えるべき「主要な単位」と「計算方法」を、HTML/CSSの例を交えて解説します。

---

### 1. 絶対単位：`px`（ピクセル）
画面上の1ドットに相当する固定の単位です。

*   **いつ使うか：** 「絶対にサイズを変えたくないもの」に使います（細い枠線、小さな影など）。
*   **デメリット：** ユーザーがブラウザの文字サイズ設定を大きくしても、`px`で指定した文字は大きくならないため、アクセシビリティ（使いやすさ）の観点から文字サイズには推奨されません。

---

### 2. フォント基準の相対単位：`rem` と `em`
現代のCSS設計で**最も重要**な単位です。

#### ① `rem` (Root em)
**「ルート（html要素）のフォントサイズ」**を 1 とした単位です。
通常、ブラウザのデフォルトは `16px` なので、`1rem = 16px` となります。

*   **設計の癖：** **文字サイズ（font-size）や大きな余白には `rem` を使うのがベストプラクティス**です。ユーザーの設定に合わせて全体が伸縮するためです。

```html
<div class="rem-card">
  <h1>タイトル (2rem = 32px)</h1>
  <p>本文テキスト (1rem = 16px)</p>
</div>
```

```css
html {
  font-size: 16px; /* 基本はブラウザ設定に従うので書かなくてもOK */
}

.rem-card {
  padding: 2rem; /* 32pxの余白 */
}

h1 {
  font-size: 2rem; /* ルートの2倍 = 32px */
}

p {
  font-size: 1rem; /* ルートと同じ = 16px */
}
```

#### ② `em`
**「その要素自身のフォントサイズ」**を 1 とした単位です。
*   **設計の癖：** **「文字の大きさに連動してほしい余白」**に使います。例えば、ボタンの文字を大きくしたとき、自動的にボタン内の余白も広げたい場合に便利です。

```html
<button class="small-btn">小さいボタン</button>
<button class="large-btn">大きいボタン</button>
```

```css
button {
  /* 上下 0.5文字分、左右 1文字分の余白を作る */
  padding: 0.5em 1em; 
}

.small-btn { font-size: 12px; } /* 余白は 6px / 12px になる */
.large-btn { font-size: 24px; } /* 余白は 12px / 24px になる */
```

---

### 3. 表示領域（画面）基準の単位：`vw` と `vh`
ブラウザの画面（ビューポート）の大きさを 100 とした単位です。

*   **`vw` (Viewport Width):** 画面の幅の1%。
*   **`vh` (Viewport Height):** 画面の高さの1%。

#### 【例：画面いっぱいのヒーロー画像】
スマホでもPCでも、必ず画面の高さぴったりに表示したい場合に使います。

**HTML:**
```html
<section class="hero">
  <h1>全面の背景画像</h1>
</section>
```

**CSS:**
```css
.hero {
  width: 100vw;  /* 画面の横幅いっぱい */
  height: 100vh; /* 画面の高さいっぱい */
  background: url('image.jpg') center/cover;
}
```

---

### 4. 割合の単位：`%`
**「親要素」のサイズ**を 100 とした単位です。

*   **注意点：** `width: 50%` は親の幅の半分ですが、`height: 50%` は親に具体的な高さが決まっていないと機能しません。

**HTML:**
```html
<div class="parent">
  <div class="child">親の半分の幅</div>
</div>
```

**CSS:**
```css
.parent {
  width: 800px;
}

.child {
  width: 50%; /* 400pxになる */
  background: gold;
}
```

---

### 5. 現代の計算関数：`calc()` と `clamp()`
単位を組み合わせて計算したり、サイズに制限をかけたりする強力な機能です。

#### ① `calc()`：異なる単位の計算
「横幅いっぱい（100%）から、20pxだけ引きたい」といった指定ができます。

```css
.sidebar-content {
  /* 100%から20px引いた幅にする（演算子の前後にスペースが必須） */
  width: calc(100% - 20px);
}
```

#### ② `clamp()`：レスポンシブなサイズ調整（新常識！）
**「最小値、推奨値、最大値」**の3つを指定します。メディアクエリを書かなくても、画面幅に合わせて文字サイズを自動調整できます。

```css
h1 {
  /* 最小 24px、画面幅に応じて 5vw、最大 48px */
  font-size: clamp(24px, 5vw, 48px);
}
```
*   **メリット：** スマホでは小さく、PCでは大きく、といった変化がこれ1行で完結します。

---

### 現代のベストプラクティス：単位の使い分けルール

初期から以下の「癖」をつけておくと、プロのコードに近づきます。

1.  **文字サイズ (`font-size`)**
    *   原則、すべて **`rem`** を使う。
2.  **要素の幅 (`width`)**
    *   **`%`** や **`vw`**、または **`max-width: 1000px`** のように「最大幅」を決めてから `100%` にする。
3.  **余白 (`padding` / `margin`)**
    *   基本は **`rem`**。
    *   ボタンの中など、文字と密接に関わる場所は **`em`**。
4.  **枠線 (`border-width`)**
    *   ここだけは **`px`**。1pxを `rem` にすると、計算の端数で線が消えたり太さがバラバラに見えることがあるためです。

### まとめ：値と単位のチェックリスト

*   [ ] `px` を多用しすぎていないか？（スマホで見た時に固定サイズで崩れる原因）
*   [ ] 文字サイズに `rem` を使っているか？
*   [ ] 画面全体を使いたい場所に `vh` / `vw` を検討したか？
*   [ ] 複雑な計算を `calc()` でシンプルに解決できないか？

「値と単位」における**アンチパターン（避けるべき書き方）**と**ベストプラクティス（推奨される書き方）**を比較します。

CSSの単位選びは、単に「見た目を整える」だけでなく、**「アクセシビリティ（誰でも使えるか）」「レスポンシブ（スマホ対応）」「メンテナンス性（直しやすさ）」**に直結します。

---

### 1. 文字サイズの指定：`px` vs `rem`

#### 【アンチパターン】すべて `px` で固定する
ユーザーがブラウザ設定で「文字を大きく表示」としていても、`px` で書かれた文字は強制的にそのサイズに固定され、無視されてしまいます。

#### 【ベストプラクティス】`rem` を使い、ユーザー設定を尊重する
`rem` はルート（ブラウザの基本設定）に対する倍率なので、ユーザーの設定に合わせて伸縮します。

**HTML:**
```html
<div class="card bad-font">
  <h2>アンチパターン (px指定)</h2>
  <p>ブラウザの文字サイズ設定を変更しても、この文字は大きくならないので不便です。</p>
</div>

<div class="card good-font">
  <h2>ベストプラクティス (rem指定)</h2>
  <p>ブラウザ設定を「大」にすると、この文字も一緒に大きくなります。これが現代の標準です。</p>
</div>
```

**CSS:**
```css
/* アンチパターン */
.bad-font h2 { font-size: 24px; }
.bad-font p  { font-size: 16px; }

/* ベストプラクティス */
.good-font h2 { font-size: 1.5rem; } /* 16px * 1.5 = 24px */
.good-font p  { font-size: 1rem; }   /* 16px * 1.0 = 16px */

.card { border: 1px solid #ccc; margin-bottom: 20px; padding: 1rem; }
```

*   **違いの観点：**
    *   **アクセシビリティ:** `rem` は視力の弱いユーザーが文字を大きくして読む権利を保障します。
    *   **一貫性:** `1.5rem` と書けば「基本の1.5倍」という意味が明確になります。


フォントサイズ変更手順（chrome）
1. **ブラウザの右上の「︙」**（三点リーダ）をクリック。
2. **「設定」**を選択。
3. 左メニューの**「デザイン」**をクリック。
4. 「フォントサイズ」の項目で、希望のサイズを選択または設定。

---

### 2. レイアウトの幅：固定幅 `px` vs 可変幅 `%` + `max-width`

#### 【アンチパターン】横幅を `px` で決める
PCでは綺麗に見えますが、スマホで見ると画面を突き抜け、横スクロールが発生して「壊れたサイト」に見えます。

#### 【ベストプラクティス】幅は `%` で、上限を `px` で決める
「基本は画面いっぱいに広がるが、PCなどの大きな画面ではこれ以上広がらない」という柔軟な指定をします。

**HTML:**
```html
<div class="container bad-width">
  固定幅 800px：スマホで見ると右側がはみ出します。
</div>

<div class="container good-width">
  可変幅：スマホでは画面に収まり、PCでは 800px で止まります。
</div>
```

**CSS:**
```css
/* アンチパターン */
.bad-width {
  width: 800px;
  background-color: #ffcdd2;
}

/* ベストプラクティス */
.good-width {
  width: 90%;         /* スマホでは左右に少し隙間を開けて広がる */
  max-width: 800px;   /* PCでも800px以上にはならない */
  margin: 0 auto;     /* 中央寄せ */
  background-color: #c8e6c9;
}

.container { height: 100px; padding: 20px; margin-top: 10px; }
```

*   **違いの観点：**
    *   **レスポンシブ:** `max-width` を使うことで、1つのコードでスマホとPCの両方に対応できます。
    *   **ユーザー体験:** 横スクロールが出るサイトは、操作性が著しく低下します。

---

### 3. ボタンの余白：`px` vs `em`

#### 【アンチパターン】上下左右の余白を `px` で固定する
ボタン内の文字サイズを大きくしたとき、余白がそのままなので、文字が枠にぶつかりそうで窮屈に見えます。

#### 【ベストプラクティス】余白に `em` を使う
`em` はその要素の文字サイズを基準にします。文字が大きくなれば、余白も自動で比例して広がるため、常にデザインのバランスが保たれます。

**HTML:**
```html
<!-- 文字を大きくしてみる -->
<button class="btn bad-padding" style="font-size: 24px;">pxボタン</button>
<button class="btn good-padding" style="font-size: 24px;">emボタン</button>
```

**CSS:**
```css
/* アンチパターン */
.bad-padding {
  padding: 10px 20px; /* 文字が大きくなっても10pxのままなので窮屈 */
  background: #eee;
}

/* ベストプラクティス */
.good-padding {
  padding: 0.5em 1em; /* 文字サイズの半分・1文字分の余白。バランスが崩れない */
  background: #ddd;
}

.btn { border: 1px solid #333; cursor: pointer; }
```

*   **違いの観点：**
    *   **メンテナンス性:** 文字サイズを変更するだけで、余白を個別に修正する必要がなくなります。
    *   **デザインの黄金比:** 常に文字と余白の比率が一定になります。

---

### 4. レスポンシブな文字：メディアクエリ vs `clamp()`

#### 【アンチパターン】画面幅ごとに細かく数値を書き換える
コードが長くなり、サイズが切り替わる瞬間に文字が「カクッ」と急に変わります。

#### 【ベストプラクティス】`clamp()` で滑らかに変化させる
1行で「最小、推奨、最大」を指定し、画面幅に合わせてヌルヌルと文字サイズが変わるようにします。

**HTML:**
```html
<h1 class="responsive-title">
  画面を広げたり狭めたりしてみてください
</h1>
```

**CSS:**
```css
/* アンチパターン（これを書くのは大変） */
h1 { font-size: 20px; }
@media (min-width: 600px) { h1 { font-size: 30px; } }
@media (min-width: 1200px) { h1 { font-size: 40px; } }

/* ベストプラクティス */
.responsive-title {
  /* 最小 1.5rem, 推奨 5vw (画面幅の5%), 最大 3rem */
  font-size: clamp(1.5rem, 5vw, 3rem);
}
```

*   **違いの観点：**
    *   **簡潔さ:** メディアクエリを何個も書く手間が省けます。
    *   **美しさ:** どんな画面幅でも、そのサイズに最適な文字サイズが自動計算されます。

---

### まとめ：単位選びの思考プロセス

| 項目 | アンチパターン | ベストプラクティス | 理由 |
| :--- | :--- | :--- | :--- |
| **文字サイズ** | `px` | **`rem`** | ユーザーのブラウザ設定を尊重するため |
| **コンテンツ幅** | `px` (固定) | **`max-width`** | スマホでの横スクロール（崩れ）を防ぐため |
| **要素内の余白** | `px` | **`em`** | 文字サイズに比例して見た目のバランスを保つため |
| **境界線(線幅)** | `rem` / `em` | **`px`** | 細い線は計算誤差で消えるのを防ぐため(1pxは1pxが安全) |
| **全画面要素** | `100%` | **`vw` / `vh`** | 親の高さに関係なく画面基準で指定したいため |

---


ご提示いただいた資料は非常に整理されており、初心者の方にとっても分かりやすい内容です。

さらに「現代のWeb制作（iPhoneから4Kまで）」という観点を強化するために、**「情報のアップデート（最新単位）」**と**「より実戦的な判断基準」**を加えて再編しました。

特に、スマホ特有の「ブラウザのアドレスバー問題」を解決する単位や、`rem`と`px`の使い分けの基準をより明確にしています。

# 【決定版】CSSの単位・使い分けガイド：レスポンシブ時代の新常識

現代のWeb制作では、デバイスごとに細かく数値を書くのではなく、**「ブラウザやユーザーの設定に計算を任せる」**のがプロの設計です。

---

### 1. 単位の「役割」一覧表（クイック参照）

まず、どの項目にどの単位を使うべきか、結論から示します。

| 項目 | 推奨単位 | 理由 |
| :--- | :--- | :--- |
| **文字サイズ** | **`rem`** | ブラウザの文字サイズ設定（アクセシビリティ）を尊重するため |
| **余白（大）** | **`rem`** | サイト全体のスケール感（文字との比率）を統一するため |
| **余白（ボタン内等）** | **`em`** | 文字を大きくした時に、余白も自動で比例させるため |
| **コンテンツ幅** | **`%` / `max-width`** | 画面からはみ出さないようにするため |
| **枠線（border）** | **`px`** | 1px未満の線が消えたり、ぼやけたりするのを防ぐため |
| **全画面の高さ** | **`dvh`** (推奨) | スマホのメニューバーで下部が隠れるのを防ぐため |

---

### 2. 各単位の詳細と「使い分けの具体例」

#### ① `rem` (Root em) ：「文字と全体の基準」
**html要素（ルート）のフォントサイズ**を 1 とした単位。
*   **いつ使う？：** 文字サイズ、セクション間の余白、コンテナの最大幅など。
*   **なぜ？：** ユーザーがブラウザ設定で「文字を大きく」した場合、サイト全体がバランスよく拡大されるため。

```css
/* ブラウザ標準 16px の場合 */
h2 {
  font-size: 1.5rem;   /* 24px相当 */
  margin-bottom: 2rem; /* 32px相当。文字が大きくなれば余白も広がる */
}
```

#### ② `em` ：「パーツ内の比例」
**その要素自身のフォントサイズ**を 1 とした単位。
*   **いつ使う？：** アイコンのサイズ、ボタン内の余白、1行目のインデントなど。
*   **なぜ？：** 文字サイズを変更した際、そのパーツの中だけで比率を維持したい場合に便利。

```css
.btn-small { font-size: 12px; padding: 0.5em 1em; } /* 余白: 6px 12px */
.btn-large { font-size: 20px; padding: 0.5em 1em; } /* 余白: 10px 20px */
/* 文字サイズを変えるだけで、黄金比のボタンが作れる */
```

#### ③ `px` ：「絶対に変えたくない固定値」
*   **いつ使う？：** 細い枠線、ごく小さな影（blur値）、画像アセットの固定サイズ。
*   **注意点：** 文字サイズに `px` を使うのは、現代では「アクセシビリティ違反」とみなされることがあります。

#### ④ `vw` / `dvh` ：「画面サイズ（ビューポート）基準」
*   **`vw` (Viewport Width):** 画面横幅の1%。
*   **`dvh` (Dynamic Viewport Height):** **【重要】** スマホのメニューバー（URL欄）が出たり消えたりしても、常に「今見えている高さ」に合わせてくれる最新の単位です。

```css
/* 古い書き方：100vh だとスマホで下部のボタンがメニューに隠れることがある */
/* 最新の書き方：dvh を使うと、メニューが出ていても綺麗に収まる */
.hero {
  height: 100dvh; 
}
```

---

### 3. 【実践】よくあるシチュエーション別の使い分け

#### ケースA：画面幅に合わせて文字を「いい感じ」にしたい
`px` や `rem` だけで指定すると、スマホで巨大すぎたり、PCで小さすぎたりします。

*   **解決策：`clamp()` 関数を使う**
    `clamp(最小値, 推奨値, 最大値)` で、メディアクエリなしのレスポンシブが実現します。

```css
h1 {
  /* 最小32px、画面幅の5%分、最大64px。その間をヌルヌル動く */
  font-size: clamp(2rem, 5vw, 4rem);
}
```

#### ケースB：サイドバーがあるレイアウト
「メインは全幅から、サイドバーの300pxを引きたい」といった場合。

*   **解決策：`calc()` 関数を使う**

```css
.main-content {
  width: calc(100% - 300px);
}
```

#### ケースC：画像の「横スクロール」を防ぎたい
画像やカード要素が、スマホ画面を突き抜けて横揺れするのを防ぐ。

*   **解決策：`max-width` を活用する**

```css
img {
  max-width: 100%; /* 親要素より大きくならない */
  height: auto;    /* アスペクト比を維持 */
}
```

---

### 4. アンチパターンと改善例

| アンチパターン | 何がダメ？ | 改善案 |
| :--- | :--- | :--- |
| `font-size: 16px;` | ブラウザの拡大設定が効かない | `font-size: 1rem;` |
| `width: 1200px;` | スマホで横スクロールが発生する | `width: 90%; max-width: 1200px;` |
| `height: 100vh;` | スマホでボタンがメニューバーに被る | `height: 100dvh;` |
| `margin: 20px;` | 文字を大きくした時に余白が狭く感じる | `margin: 1.25rem;` |

---

### まとめ：プロの思考プロセス
1.  **基本は `rem`：** 文字も余白も、まずは `rem` で組み立てる。
2.  **パーツは `em`：** ボタンやバッジなど、中身の文字に依存するものは `em`。
3.  **枠線は `px`：** 消えてほしくない境界線だけは `px`。
4.  **幅は `%` と `max-width`：** 常に「可変（フレキシブル）」にしつつ、PCでの広がりすぎを抑える。
5.  **高さは `dvh`：** 全画面表示なら、スマホの挙動に強い `dvh`。

このルールを守るだけで、**「どんな画面で見ても崩れず、誰にとっても読みやすい」**洗練されたコーディングになります。
