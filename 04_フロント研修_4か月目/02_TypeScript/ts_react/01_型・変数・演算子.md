# 第1回：型・変数・演算子
**〜JavaScriptの柔軟性とTypeScriptの安全性を理解する〜**

## 1. 変数宣言：`const` と `let` [JS]

Javaでは `final` を使って定数を定義しますが、JS/TSでは「再代入しない変数はすべて `const`」で宣言するのが鉄則です。

### サンプルコード
```typescript
// 1. const: 再代入不可（Javaの final に相当）
const threshold = 100;
// threshold = 200; // コンパイルエラー

// 2. let: 再代入可能
let count = 0;
count += 1;

// 3. var: （非推奨）
// Javaの古い書き方のようなスコープの曖昧さがあるため、現代のJS/TS開発では一切使いません。
```

### 比較：宣言方法の使い分け
| 特徴 | `const` | `let` | `var` |
| :--- | :--- | :--- | :--- |
| **再代入** | 不可 | 可能 | 可能 |
| **スコープ** | ブロックレベル `{}` | ブロックレベル `{}` | 関数レベル |
| **推奨度** | **最優先で使う** | 再代入が必要な場合のみ | **絶対に使わない** |

**ベストプラクティス：**
- ReactのState（状態管理）を除き、通常の変数は **9割以上 `const`** になります。副作用を減らすため、まずは `const` で書けないか検討してください。

## 2. 基本的な型定義 [TS]

Javaは「名前論理型（クラス名で型を判定）」ですが、TSは「構造的部分型（持っているプロパティで型を判定）」という違いがあります。

### サンプルコード
```typescript
// 基本プリミティブ
const message: string = "Hello React";
const price: number = 2980; // 整数も浮動小数点も number
const isActive: boolean = true;

// 配列の定義
const scores: number[] = [10, 20, 30];

// 型推論：右辺から型が明らかな場合、型注釈を省略するのがTS流です
const city = "Tokyo"; // 自動的に string 型とみなされる
```

### 特殊な型：`any` と `unknown` [TS]
Javaの `Object` に近いものですが、扱いが異なります。

```typescript
// any: 何でも許容する（型チェックを放棄する）
let data: any = 1;
data = "string";
data.nonExistentMethod(); // 実行時エラーになるがコンパイルは通ってしまう

// unknown: 何でも入るが、使う前に「型ガード」が必要（安全な Object）
let value: unknown = "Hello";
// console.log(value.toUpperCase()); // エラー：型が不明なため

if (typeof value === "string") {
    console.log(value.toUpperCase()); // OK：stringであることが確定した（型ガード）
}
```

## 3. 列挙型とリテラル型 [TS]

Javaの `Enum` に相当する機能ですが、React開発では **Union型 + リテラル型** の組み合わせが最も好まれます。

### サンプルコード
```typescript
// 方法1: Enum [TS] (Javaに近いが、生成されるJSが複雑になるため避けられる傾向にある)
enum Status {
    Pending,
    Success,
    Error
}
const currentStatus: Status = Status.Success;

// 方法2: Union型 + リテラル型 [TS] (★推奨：Reactで最も多用される)
type TaskStatus = "pending" | "success" | "error";

const myStatus: TaskStatus = "success"; 
// const errorStatus: TaskStatus = "draft"; // エラー：指定した文字列以外は許容されない
```

### 比較
| 方法 | メリット | デメリット |
| :--- | :--- | :--- |
| **Enum** | Javaエンジニアに馴染みがある | JSに変換した際にコード量が増える。 |
| **Union型** | 軽量、直感的、型補完が強力 | 文字列のタイポには強いが、実行時の値の一覧取得が工夫が必要 |

## 4. `null` と `undefined` [JS/TS]

Javaでは `null` のみですが、JS/TSには「値がない」状態が2つあります。

- **`undefined`**: 変数が宣言されたが値が割り当てられていない状態。（JSのデフォルト）
- **`null`**: 明示的に「空」であることを示す状態。

### サンプルコード
```typescript
let x: number | undefined; // Union型で「数値または未定義」を許容
console.log(x); // undefined

let y: number | null = null; // 明示的にnullを代入
```

**アンチパターン：**
- Javaの癖で `null` を多用しがちですが、TS（特にReact周辺）では **「基本は `undefined` を使い、APIレスポンスなどで明示的に空を示す場合のみ `null` を使う」** というのが一般的です。

## 5. モダンな演算子：React開発の必須知識 [JS]

Javaエンジニアが最も感動し、かつ多用するのがこれらの演算子です。

### 1. オプショナルチェイニング (`?.`)
ネストされたプロパティに安全にアクセスします。Javaの `Optional.map(...).orElse(...)` を極限まで簡略化したような動きです。

```typescript
type User = {
    profile?: {
        name: string
    }
};

const user: User = {};

// Javaなら: if (user.profile != null) { ... }
// TSなら:
const name = user.profile?.name; // profileがなければ undefined を返し、エラーにならない
```

### 2. Null合体演算子 (`??`)
`null` または `undefined` の場合のみデフォルト値を返します。

```typescript
const input: string | undefined = undefined;

// inputが null/undefined なら "Guest" を入れる
const userName = input ?? "Guest"; 

// 補足：論理和 (||) との違い
// || は 0 や ""（空文字）も偽性と判定してデフォルト値を適用してしまう
const count = 0;
console.log(count ?? 10); // 0 (意図通り)
console.log(count || 10); // 10 (0が無視されるためバグの原因になりやすい)
```

## 6. 比較演算子： `===` を使え [JS]

Javaでは文字列の比較に `.equals()` を使いますが、JS/TSでは `===` を使います。

### サンプルコード
```typescript
// 厳密等価演算子 (===) ★常にこれを使う
console.log(1 === 1);    // true
console.log(1 === "1");  // false (型が違うので false)

// 抽象等価演算子 (==) ★絶対に使わない
console.log(1 == "1");   // true (勝手に型変換される。バグの温床)
```

---

## まとめ：

1.  **型推論を活かす**: すべてに型を書くのではなく、推論に任せられるところ（初期値がある変数など）は省略してコードをスッキリさせましょう。
2.  **`any` を禁止する**: Javaで `Object` ばかり使わないのと同様に、`any` を使うとTSを使う意味がなくなります。
3.  **Union型に慣れる**: `string | number` のような「AまたはB」という表現はReactのProps（コンポーネントの引数）で非常に強力な武器になります。
4.  **`===` と `??` と `?.` を使いこなす**: これだけでコードの堅牢性が劇的に上がります。
