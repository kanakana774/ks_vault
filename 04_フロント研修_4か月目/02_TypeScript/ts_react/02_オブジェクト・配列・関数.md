# 第2回：オブジェクト・配列・関数
**〜Reactのデータ操作とコンポーネントの本質を理解する〜**

## 1. オブジェクトの定義と型 [JS/TS]

Javaではデータ保持のためにクラス（POJO）を作りますが、JS/TSでは**オブジェクトリテラル**を使ってその場でデータを作ります。

### サンプルコード
```typescript
// 1. 型の定義（Javaのインターフェースに近い） [TS]
type User = {
  readonly id: number; // 読み取り専用
  name: string;
  email: string;
  age?: number;        // オプショナル（あってもなくても良い）
};

// 2. オブジェクトの生成 [JS]
const user: User = {
  id: 1,
  name: "Tanaka",
  email: "tanaka@example.com",
};

// 3. プロパティへのアクセス [JS]
console.log(user.name);
```

### 比較：`type` (型エイリアス) vs `interface` [TS]
オブジェクトの型を定義する方法は2つあります。

| 特徴 | `type` | `interface` |
| :--- | :--- | :--- |
| **拡張性** | 同名の定義は不可 | 同じ名前で定義すると自動でマージされる |
| **用途** | オブジェクト以外（Union型など）も定義可 | オブジェクトの定義に特化 |
| **Reactでの主流** | **非常に多い（柔軟なため）** | 大規模開発やライブラリ開発で好まれる |

**ベストプラクティス：**
React開発では、まずは **`type`** を使うのが一般的です。Union型（`A | B`）と組み合わせて柔軟な定義ができるためです。

## 2. オブジェクトの破壊的変更とイミュータビリティ [JS]

Reactでは「元のオブジェクトを直接書き換えない（不変性/Immutability）」ことが極めて重要です。

### サンプルコード
```typescript
const originalUser: User = { id: 1, name: "Tanaka", email: "t@ex.com" };

// ❌ アンチパターン：プロパティを直接書き換える
// Reactの再レンダリングが検知されない原因になります
// originalUser.name = "Sato"; 

// ✅ ベストプラクティス：スプレッド構文 (...) で新しいオブジェクトを作る
const updatedUser = {
  ...originalUser, // 全コピー
  name: "Sato"      // 一部だけ上書き
};

console.log(originalUser.name); // Tanaka (元のまま)
console.log(updatedUser.name);  // Sato (新しく生成)
```

## 3. 配列の操作 (map, filter) [JS]

Javaの Stream API (`map`, `filter`, `collect`) とほぼ同じ概念です。Reactでは、リスト表示のために `map` を多用します。

### サンプルコード
```typescript
const users = [
  { id: 1, name: "Tanaka", active: true },
  { id: 2, name: "Sato", active: false },
  { id: 3, name: "Suzuki", active: true },
];

// 1. map: 要素を変換して新しい配列を作る（Reactのリストレンダリングで必須）
const names = users.map(user => user.name); 
// ["Tanaka", "Sato", "Suzuki"]

// 2. filter: 条件に合うものだけ抽出する
const activeUsers = users.filter(user => user.active);
// [{id: 1...}, {id: 3...}]

// 3. スプレッド構文による配列の追加（元の配列を壊さない）
const newUser = { id: 4, name: "Ito", active: true };
const newUsers = [...users, newUser]; 
```

## 4. 分割代入 (Destructuring) [JS]

オブジェクトや配列から特定の値を抜き出す構文です。ReactのProps受け取りで毎日使います。

### サンプルコード
```typescript
const member = { id: 100, userName: "Alice", role: "admin" };

// 1. オブジェクトの分割代入
// Javaなら: String name = member.getUserName();
const { userName, role } = member;
console.log(userName); // "Alice"

// 2. 配列の分割代入 (Reactの useState で利用)
const colors = ["red", "blue"];
const [firstColor, secondColor] = colors;
console.log(firstColor); // "red"
```

## 5. 関数 (アロー関数) [JS/TS]

現代のReact（Functional Component）では、従来の `function` 宣言よりも **アロー関数** が好まれます。

### サンプルコード
```typescript
// 1. 基本的なアロー関数 [JS]
// (引数) => { 処理 }
const add = (a: number, b: number): number => {
  return a + b;
};

// 2. 簡略表記（1行の場合は return と { } を省略可能）
const multiply = (a: number, b: number): number => a * b;

// 3. オブジェクトの分割代入を引数で使う (Reactコンポーネントの基本形) [JS/TS]
type Props = { title: string; count: number };

const displayTitle = ({ title, count }: Props): void => {
  console.log(`${title}: ${count}`);
};

displayTitle({ title: "Score", count: 10 });
```

### 比較：関数宣言 vs アロー関数 [JS]
| 比較項目 | `function` 宣言 | アロー関数 (`const = () =>`) |
| :--- | :--- | :--- |
| **巻き上げ** | あり（宣言前でも呼べる） | なし（宣言後のみ実行可） |
| **`this` の拘束** | 呼び出し元に依存する | 宣言時のスコープを維持する |
| **Reactでの利用** | コンポーネント定義で見かける | **イベントハンドラやHooksで主流** |

**ベストプラクティス：**
一貫性のため、Reactコンポーネントも中のロジックもすべて **アロー関数** で統一するのが今のトレンドです。

## 6. 特殊な型操作 (Generics) [TS]

Javaのジェネリクス (`List<T>`) と概念は同じです。

### サンプルコード
```typescript
// Tは型引数
function wrapInArray<T>(value: T): T[] {
  return [value];
}

const stringArr = wrapInArray<string>("Hello"); // string[] になる
const numberArr = wrapInArray(123);             // 型推論で number[] になる
```

---

## まとめ

1.  **Immutabilityを意識する**: `user.name = "xxx"` ではなく `{...user, name: "xxx"}`。
2.  **`map` は超重要**: 配列からUIのリストを作る際に `users.map(user => <li>{user.name}</li>)` のように書きます。
3.  **分割代入を使いこなす**: 関数の引数で `(props)` と受け取るのではなく `({ name, age })` と受け取るのがReactの標準です。
4.  **アロー関数に慣れる**: `function` キーワードを見る機会は減っていきます。
