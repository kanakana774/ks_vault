## Todo に状態と期限日を追加する機能

- 課題2の処理に加えて Todo に状態と期限日を持たせる機能を追加する。
- 状態は `NOT_STARTED`、`IN_PROGRESS`、`COMPLETED` のいずれかとする。
- 期限日は任意項目とし、未設定を許可する。

### Todo の一覧取得

1. リクエストを受け取る。

2. バリデーションチェックにより以下のリクエスト不正の処理を行う。
   - `limit`が 1 未満だった場合
   - `status`に定義外の値が指定された場合
   - `dueDateTo`の日付形式が不正な場合

3. 任意のクエリパラメータで受け取った`limit`、`title`、`status`、`tagId`、`dueDateTo`を元に、Todo 情報を取得する。<br>
   同時に取得した Todo 情報に紐づく Tag の情報を取得する。
   - 検索結果が 0 件の場合、空のリストを取得
   - 検索結果が 1 件以上の場合、レスポンスとして検索結果を取得

4. 取得した Todo 情報に状態と期限日を含めてレスポンスとして返却する。

---

### Todo の登録

1. リクエストを受け取る。

2. バリデーションチェックにより以下のリクエスト不正の処理を行う。
   - `title`が未入力だった場合
   - `title`が 1 文字以上 30 文字以内の指定を超えている場合
   - `content`が未入力だった場合
   - `content`が 1 文字以上 100 文字以内の指定を超えている場合
   - `tags`のサイズが 0 件以上 5 件以内でない場合
   - `status`に定義外の値が指定された場合
   - `dueDate`の日付形式が不正な場合

3. Tag の存在チェックを行う。
   - 指定した Tag が存在しなかった場合
     - エラーをスローする(エラー内容はエラー設計書を参照する)。

4. Todo を登録する。
   - `status`が未指定の場合は `NOT_STARTED` を設定して登録する。
   - Todo の登録処理を行う。

5. Todo と Tag の紐づきを登録する。
   - Todo_Tag の登録処理を行う。

6. ステータスコード(201)と登録した Todo にアクセスできるように TodoId を返す。

### Todo の 1 件取得

1. リクエストを受け取る。

2. Todo の存在チェックを行う。
   - 指定した Todo が存在しなかった場合
     - エラーをスローする(エラー内容はエラー設計書を参照する)。

   - 指定した Todo が存在した場合
     - Todo を 1 件取得する。<br>
       同時に取得した Todo 情報に紐づく Tag の情報を取得する。

3. 取得した Todo 情報に状態と期限日、および Tag 情報を含めてレスポンスとして返却する。

---

### Todo の更新

1. リクエストを受け取る。

2. バリデーションチェックにより以下のリクエスト不正の処理を行う。
   - `title`が未入力だった場合
   - `title`が 1 文字以上 30 文字以内の指定を超えている場合
   - `content`が未入力だった場合
   - `content`が 1 文字以上 100 文字以内の指定を超えている場合
   - `tags`のサイズが 0 件以上 5 件以内でない場合
   - `status`に定義外の値が指定された場合
   - `dueDate`の日付形式が不正な場合
   - `version`が未入力の場合

3. Todo の存在チェックを行う。
   - 指定した Todo が存在しなかった場合
     - エラーをスローする(エラー内容はエラー設計書を参照する)。

4. Tag の存在チェックを行う。
   - 指定した Tag が存在しなかった場合
     - エラーをスローする(エラー内容はエラー設計書を参照する)。

5. 楽観ロックチェックを行う。
   - 指定した Todo が最新の情報でない(リクエストボディの更新回数と、指定した Todo 情報の更新回数が一致しない)場合
     - エラーをスローする(エラー内容はエラー設計書を参照する)。

6. エラーが存在しない場合、Todo を更新する。
   - Todo 情報を更新する。
   - 状態と期限日を更新する。

7. Todo 情報に紐づく Tag 情報を更新する。
   - Todo_Tag テーブルに紐づいていた情報を削除し、新たに Todo 情報に Tag 情報の紐づけを登録する。

8. ステータスコード(204)を返す。

---

### Todo の 1 件削除

1. リクエストを受け取る。

2. バリデーションチェックにより以下のリクエスト不正の処理を行う。
   - `version`が未入力の場合

3. Todo の存在チェックを行う。
   - 指定した Todo が存在しなかった場合
     - エラーをスローする(エラー内容はエラー設計書を参照する)。

4. 楽観ロックチェックを行う。
   - 指定した Todo が最新の情報でない(リクエストボディの更新回数と、指定した Todo 情報の更新回数が一致しない)場合
     - エラーをスローする(エラー内容はエラー設計書を参照する)。

5. エラーが存在しない場合、Todo を 1 件物理削除する。

6. Todo_Tag テーブルに紐づいていた情報を削除する。

7. ステータスコード(204)を返す。
