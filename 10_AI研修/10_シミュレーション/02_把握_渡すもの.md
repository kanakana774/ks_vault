## 1. 素で叩くプロンプト（15分・1回だけ）

**何も渡さずに叩かせる。出力は捨てさせない。**

```

```

- 出力は保存させる（段⑤で、整えて渡した結果と並べる）
- **演習にしない。** 比較の材料を1つ取るだけ

## 2. 空白を挙げさせるプロンプト（60分・段②の本体）

```
このリポジトリと設計書を読んで、Todo と Tag、および両者の紐づけを
実装するとします。

実装する前に「確認しないと決められないこと」を挙げてください。

- 各項目について、根拠として どの資料のどこを読んだか を必ず示してください。
- 実装は始めないでください。挙げるだけにしてください。
```

> **「根拠の場所」を書かせるのが要。** これが無いと研修生が判定できず、判定できないと段②が成立しない。
> 実務でも同じ（「どこ見て言ってる？」を先に聞く）。

## 3. Q&A票の雛形（提出物）

**AIが挙げた項目を1件ずつ3判定に仕分ける。**

| # | AIが挙げた項目 | AIが示した根拠 | 判定 | 自分が書くこと |
|---|---|---|---|---|
| 1 | | | ①／②／③ | |
| 2 | | | ①／②／③ | |

### 判定の意味

| 判定 | 意味 | 「自分が書くこと」に何を書くか |
|---|---|---|
| **① 書いてあった** | **AIの誤検出。**探したら設計書に書かれていた | **資料名と場所**（例: `Todo機能.md` の「Todo の更新」3-4） |
| **② 空白・自分で決められる** | 書かれていないが、自分の判断で決めてよい | **こう決めた ＋ その理由** |
| **③ 空白・自分では決められない** | 書かれておらず、判断に権限や背景が要る | **誰に聞くか ＋ 何を聞くか** |

### 研修生に言うこと

- **①が一番多く出るのが普通です。** AIの指摘の大半は自分で潰せます
- **②と③の線引きに正解はありません。** ただし**迷ったら③**にしてください。実務で困るのは、②にすべきものを③にしたときではなく、**③にすべきものを②にしたとき**です
- **①を見落としたまま②③に振ると、読んでいないことが分かります**

> **講師はここを見る。** ①の見落としが評価の掛かりどころ（`07_実施計画.md` §3）。
