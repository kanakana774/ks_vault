## Step 0. 事前準備（実験期間中に1回だけ）

### 0-1. `additionalDirectories` を無効化する ★これが最重要

`C:\Users\kanamaru\.claude\settings.json` を開き、キー名を変えて無効化する。

```json
  "_additionalDirectories_OFF_for_experiment": [
    "C:\\aevic_dev\\review"
  ]
```

**なぜ**: この設定があると、**どのセッションからも `C:\aevic_dev\review` が読める**。そこには渡していない資料（コーディングガイド・講義資料）と、`todo-app-api` の `.git` 経由で **`answer-sample*`（模範解答）** がある。実際に P2 の1回目で AI が勝手に読みに行った。

**実験が全部終わったらキー名を戻す**（戻さないと `/trainee-review` のレビュー作業ができなくなる）。→ Step 6

### 0-2. DB を用意する

`application.properties` は `jdbc:postgresql://localhost:5432/todo`（user=todo / password=todo）を指している。**研修生と同じ条件にするため、先に作っておく。**


**`git archive` を使う。** clone やコピーだと `.git` が付いてきて、`answer-sample` に到達できてしまう。

Git Bash で実行:

```bash
EXP="/c/Users/kanamaru/Desktop/実験/p2b"
mkdir -p "$EXP/todo-app-api-develop"
git -C /c/aevic_dev/review/todo-app-api archive develop | tar -x -C "$EXP/todo-app-api-develop"
```

確認（**`.git` が無いこと**）:

```bash
ls -a "$EXP/todo-app-api-develop" | grep -c '^\.git$'   # → 0 であること
```

### 3-2. `$EXP\CLAUDE.md`

```markdown
# 作業範囲の制約

このディレクトリは閉じた実験環境である。作業も参照も、**このディレクトリ配下だけ**で行うこと。

## 参照してよいもの
このディレクトリ配下のファイルのみ。

## 参照してはいけないもの（厳守）
- `C:\aevic_dev\` 配下のすべて
- `C:\Users\kanamaru\Documents\aevic\` 配下のすべて
- `C:\Users\kanamaru\Documents\MyWork\` 配下のすべて

これらには同じ課題の模範解答と、ここに置いていない補助資料が含まれる。読むとこの作業の意味がなくなる。
「関連する資料がどこかにあるはず」と探しに行かないこと。**ここに置かれているものが、渡された情報のすべてである。**
情報が足りないと判断した場合は、探しに行かず、**何が足りないかを報告する**こと。

`git` コマンドは使わない。
```

> **注**: この `CLAUDE.md` は条件の一部になる。「足りなければ報告せよ」が、後述の「書かれていないことは明示せよ」を補強する副作用がある。記録シートに「CLAUDE.md あり」と書いておく。

`02_実験_プロンプト差の検証.md` §4 の記録シートを埋める。**その場で埋める。後から思い出せない。**

### P2 で最も注意して見る分岐点（優先順）

1. **`core/exception` の既存機構を使うか、`@RestControllerAdvice` で自作するか** ← P1 では自作した。最重要

3. `todo_checks.xml` を自分から読むか
4. 7層に素直に従うか、勝手に簡略化するか
5. Javadoc を書くか
6. DB / Flyway をどうするか（マイグレーションSQLは無い）
7. 動くところまで行くか
