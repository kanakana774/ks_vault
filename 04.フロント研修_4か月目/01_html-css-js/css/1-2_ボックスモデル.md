CSSの「ボックスモデル」は、デザイン崩れを防ぐために最も重要な概念です。
「すべての要素は四角い箱（ボックス）である」という前提に立ち、その箱がどのように構成され、どのようにサイズが計算されるかを定義します。

ここを適当に済ませると、**「幅を100%にしたはずなのに、なぜか横に突き抜けて崩れる」**といった問題に直面します。

---

### 1. ボックスの4つの領域

すべての要素（`div`, `p`, `button`など）は、中心から外側に向かって以下の4つの層でできています。

1.  **Content（コンテンツ）**: 文字や画像が表示される領域。
2.  **Padding（パディング）**: コンテンツと枠線の間の**内側の余白**。
3.  **Border（ボーダー）**: パディングの外側にある**枠線**。
4.  **Margin（マージン）**: 枠線の外側にある**外側の余白**。他の要素との距離。

#### 具体例でイメージする：
「額縁に入った絵」を想像してください。
*   絵そのもの ＝ **Content**
*   絵と額縁の間の白い余白 ＝ **Padding**
*   額縁そのもの ＝ **Border**
*   隣の絵との間隔 ＝ **Margin**

**※重要:** 背景色（`background-color`）は、**Borderの内側（Content + Padding）**に塗られます。Marginは常に透明です。

---

### 2. 【最重要】ボックスサイズの計算（box-sizing）

ここが現代のCSS設計で最も重要なポイントです。CSSには「サイズの計算方法」が2種類あります。

#### A. 標準モデル (`content-box`)：昔のデフォルト
`width` で指定した数値が **Content の幅だけ**を指す設定です。

*   **例:** `width: 200px; padding: 20px; border: 5px;`
*   **実際の表示幅:** 200 + 20(左) + 20(右) + 5(左) + 5(右) = **250px**
*   **問題点:** 「200pxの箱を作ったつもりが、余白のせいで250pxになった」となり、計算が非常に面倒です。

#### B. 代替モデル (`border-box`)：現代の標準
`width` で指定した数値の中に **Padding と Border も含める**設定です。

*   **例:** `width: 200px; padding: 20px; border: 5px;`
*   **実際の表示幅:** **200px** のまま。
*   **内部の動き:** Content領域が自動的に縮小して（この場合150pxになる）、全体の幅を200pxに保ちます。
*   **利点:** 直感的で、レイアウトが崩れません。

#### 現代のベストプラクティス（癖付けるべき設定）
**すべての要素を強制的に `border-box` に設定する**ことからプロジェクトを始めます。

```css
/* プロジェクトの最初に必ず書く「リセットCSS」の定番 */
*, *::before, *::after {
  box-sizing: border-box;
}
```
これを書くことで、「幅100%に指定したのに、パディングのせいで画面を突き抜ける」といった事故を100%防げます。

---

### 3. 外側の余白（Margin）の特殊ルール

マージンには、初心者を悩ませる特有の挙動があります。

#### マージンの相殺（Margin Collapsing）
上下に並んだ要素にマージンを設定すると、**「足し算」ではなく「重なり」**ます。

*   **例:**
    *   上の要素に `margin-bottom: 30px;`
    *   下の要素に `margin-top: 20px;`
*   **結果:** 要素の間隔は 50px ではなく **30px（大きい方）** になります。

※これは「要素間の間隔を一定に保つ」ための仕様ですが、最初は混乱するので「上下のマージンは重なるもの」と覚えておいてください。

---

### 4. 表示形式（display）によるボックスの違い

ボックスには大きく分けて2つの「タイプ」があります。

#### ブロックボックス (`display: block;`)
*   `div`, `h1`, `p`, `section` など。
*   **特徴:** 必ず新しい行から始まり、親要素の幅いっぱいに広がります。`width`, `height`, `margin`, `padding` がすべて有効です。

#### インラインボックス (`display: inline;`)
*   `span`, `a`, `strong` など。
*   **特徴:** 文章の一部として扱われ、新しい行にはなりません。
*   **注意:** **`width` と `height` が効きません。** また、上下の `margin` も正しく適用されません。
*   **解決策:** 「インラインのように並べたいけど、サイズも指定したい」ときは `display: inline-block;` を使います。

---

### 5. 現代の設計・整理のコツ

ボックスモデルを意識した、保守しやすい書き方の癖です。

1.  **余白のルールを統一する:**
    *   「要素の**下**と**右**にだけマージンをつける」のようにルールを決めると、マージンの相殺に悩まされにくくなります。
2.  **ネガティブマージン（負の値）を避ける:**
    *   `margin-top: -20px;` のような書き方は、無理やり位置を調整する際によく使われますが、レイアウトが壊れる原因になります。できるだけ Flexbox や Grid で解決しましょう。
3.  **論理プロパティ（Modern!）を使う:**
    *   最近は `margin-left` の代わりに `margin-inline-start` と書く手法があります。これは、多言語対応（右から左に読む言語など）を見据えた現代的な書き方です。最初は `margin-left` で十分ですが、知識として持っておくと良いでしょう。

MDNの「ボックスサイズ（Box Sizing）」と「ボックス配置（Box Alignment）」のガイドをベースに、現代のCSS開発で不可欠な知識を徹底的に解説します。


### 1. ボックスサイズ決定の全貌 (Box Sizing)

前回触れた `content-box` と `border-box` をより深く、実用的な視点で掘り下げます。

#### 外的サイズ指定 vs 内的サイズ指定
現代のCSSでは、サイズの決まり方には2つのアプローチがあります。

1.  **外的サイズ指定 (Extrinsic Sizing):**
    *   作者（あなた）が `width: 300px` のように直接数値を指定すること。
    *   箱の大きさは固定され、中のコンテンツが多くても箱は広がりません（はみ出します）。
2.  **内的サイズ指定 (Intrinsic Sizing):**
    *   中のコンテンツ（文字や画像）の量に合わせて、ブラウザが自動でサイズを決めること。
    *   プロパティ値: `min-content`, `max-content`, `fit-content`

#### 便利な新しいキーワード
*   **`max-content`**: 改行せず、コンテンツが一番長く広がるサイズ。
*   **`min-content`**: 可能な限り改行し、一番長い単語の幅に合わせるサイズ。
*   **`fit-content`**: 基本は `max-content` ですが、親要素の幅を超えそうなときは自動的に改行して収まる便利な設定です。

#### 現代のベストプラクティス：グローバルリセット
MDNのガイドでも示唆されている通り、以下のコードは現代のWeb制作における「儀式」です。

```css
html {
  box-sizing: border-box;
}

*, *::before, *::after {
  box-sizing: inherit;
}
```
*   **なぜ `inherit`（継承）を使うのか？**: すべてに `border-box` を強制するのではなく、`html` に設定してそれを継承させることで、特定のコンポーネントだけ `content-box` に戻したい（サードパーティ製ツールを使う際など）場合に柔軟に対応できるためです。

### 2. ボックス配置 (Box Alignment)

これまでは Flexbox や Grid 固有の機能だと思われていましたが、現在は「ボックス配置モジュール」として統一されています。**「どこに・どう置くか」**を制御する強力なツールです。

重要なのは、**「主軸（Main Axis）」**と**「交差軸（Cross Axis）」**の概念です。

#### A. コンテンツ全体の分配 (Distribution)
親要素の中に余ったスペースがあるとき、子要素たちをどう並べるかを決めます。

*   **`justify-content`**: 主軸方向（Flexboxなら通常は横、Gridならインライン方向）の配置。
    *   `center`: 中央寄せ
    *   `space-between`: 両端に寄せて、間を均等に
    *   `space-around`: 各要素の周りに均等な隙間
*   **`align-content`**: 交差軸方向（複数行になったときの行ごとの間隔など）の配置。

#### B. 個別のアイテムの配置 (Alignment)
親要素の「行」の中で、アイテムを上下（または左右）のどこに置くかを決めます。

*   **`align-items`**: 親要素に書く。すべての要素をまとめて制御（例：すべて中央に揃える）。
*   **`align-self`**: 子要素に書く。その要素だけ個別に上書きする（例：これだけ下に置く）。
*   **`justify-items` / `justify-self`**: **※主にGridで使用。** セルの中での配置を決めます。

#### C. 一括指定プロパティ (Shorthands)
コードを短く書くために、現代では以下のショートハンドが多用されます。
*   **`place-content`**: `align-content` と `justify-content` を一度に指定。
*   **`place-items`**: `align-items` と `justify-items` を一度に指定。

```css
/* 上下左右、完全中央揃えの決定版 */
.parent {
  display: grid;
  place-items: center;
}
```

#### D. Gap（ギャップ）の活用
ボックス配置において、マージンの代わりに使われるのが `gap` プロパティです。
*   **`column-gap`**: 列の間の隙間
*   **`row-gap`**: 行の間の隙間
*   **`gap`**: 両方を一度に指定
*   **利点**: マージンと違い、「要素と要素の間」だけに隙間ができるため、最初や最後の要素の余白を消す処理（`last-child` など）が不要になります。

### 3. ボックスモデルに関する「その他の重要事項」

MDNのガイドを網羅しつつ、実戦で必ず役立つ知識を追加します。

#### ① オーバーフロー (Overflow)
箱（ボックス）のサイズを固定したとき、中身がはみ出した場合の処理です。
*   `overflow: visible`: はみ出したまま表示（デフォルト）。
*   `overflow: hidden`: はみ出した分を隠す。
*   `overflow: auto`: はみ出した場合のみスクロールバーを表示（**最も推奨**）。
*   `overflow: scroll`: 常時スクロールバーを表示。

#### ② 置換要素 (Replaced Elements) の特殊性
`<img>` や `<video>` は「置換要素」と呼ばれ、普通のボックスとは少し挙動が異なります。
*   これらは元々「画像自体のサイズ」を持っています。
*   **`object-fit: cover;`**: 現代の必須知識。画像の比率を保ったまま、指定したボックスサイズいっぱいに広げ、はみ出した分をトリミングします。背景画像のような扱いが `<img>` タグで可能になります。

#### ③ マージンの相殺が起きない条件
前回の「マージン相殺」は、以下のような場合には**起きません**。
*   `display: flex` や `grid` の中の要素（子要素同士）。
*   `position: absolute` で浮いている要素。
*   片方の要素に `padding` や `border` が挟まっている場合。
*   これを逆手に取り、マージン相殺を避けるために親要素に `padding: 1px` を入れるというテクニックもあります。

#### ④ 論理プロパティ (Logical Properties)
現代の設計で最も「プロっぽい」書き方です。
これまでの `margin-left`, `padding-top` といった「物理的な位置」ではなく、文章の流れ（書字方向）に基づいた指定です。

*   `margin-inline-start`: 横書きなら「左」、右から読む言語なら「右」のマージン。
*   `margin-block-start`: 上のマージン。
*   `padding-inline`: 左右のパディング。
*   `padding-block`: 上下のパディング。

**なぜこれを使うか？**: 多言語対応が容易になるだけでなく、Flexboxなどで `flex-direction` を変えたときにも意図した方向に余白がつきやすいため、コンポーネント設計と非常に相性が良いです。
