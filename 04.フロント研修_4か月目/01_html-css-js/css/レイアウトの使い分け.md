現代のCSS設計において、レイアウト（配置）を制御する手法は「何でもできる」からこそ、**「どれをどの場面で使うべきか」の使い分け**が設計の美しさを左右します。

これまでの内容を整理し、**現代の推奨・非推奨・注意点**をガイドラインとしてまとめます。

---

### 1. レイアウト手法の優先順位（現代のスタンダード）

基本的には、以下の優先順位で検討するのが「現代的な書き方」です。

| 順位 | 手法 | 主な用途 | 推奨度 |
| :--- | :--- | :--- | :--- |
| **1** | **Flexbox** | コンポーネント単位（ナビ、ボタン、リスト）の整列 | **最高（メイン）** |
| **2** | **Grid** | ページ全体の枠組み、複雑なタイル状のレイアウト | **高い（構造用）** |
| **3** | **Position** | 重ね合わせ、固定配置（バッジ、ヘッダー固定など） | **限定的（補助）** |
| **4** | **Margin/Padding** | 要素間の微細な距離調整 | **必須（隙間用）** |
| **5** | **Float** | 文章の中での画像の回り込み | **低い（ほぼ使わない）** |

---

### 2. 各手法の詳細：推奨・非推奨・注意点

#### ① Flexbox（フレキシブルボックス）
*   **【推奨】**
    *   「横並び」や「縦並び」の基本すべて。
    *   要素を等間隔に並べる（`justify-content: space-between`）。
    *   上下中央揃え。
*   **【非推奨】**
    *   複雑な2次元（縦と横が密接にリンクした）の表のようなレイアウト（これはGridの役目）。
*   **【注意点】**
    *   子要素が勝手に縮んでしまうことがあるので、縮ませたくない場合は `flex-shrink: 0;` を使う。

#### ② CSS Grid（グリッド）
*   **【推奨】**
    *   「ヘッダー・メイン・サイドバー・フッター」といったページ全体の骨組み。
    *   同じサイズのカードを綺麗に並べるギャラリー。
*   **【非推奨】**
    *   単一のボタン内のアイコン配置など、単純な1行の整列（Flexboxの方が手軽）。
*   **【注意点】**
    *   IE11などの古いブラウザ対応が必要な現場では、挙動が異なるため注意が必要（※現在はほぼ無視してOKなケースが増えています）。

#### ③ Positioning（ポジショニング）
*   **【推奨】**
    *   「画像の上に文字を重ねる」「右上に通知バッジを置く」。
    *   スクロールしてもついてくるヘッダー（`fixed` または `sticky`）。
*   **【非推奨（禁忌）】**
    *   **通常の要素を並べるために `absolute` を使うこと。**（中身が増えた時に親要素を突き破る原因になります）
*   **【注意点】**
    *   `z-index`（重なり順）がカオスになりやすい。「100万」のような適当な数字を使わず、10, 20...とルール化する。

#### ④ Margin / Padding / Gap
*   **【推奨】**
    *   要素間の隙間は **`gap`** を第一選択にする（Flex/Grid使用時）。
    *   要素の内側の余白は常に `padding`。
*   **【注意点】**
    *   `margin` の相殺（上下の隙間が重なる現象）に注意。
    *   親要素を突き抜けるような「ネガティブマージン（マイナスの値）」は、他に手段がない時以外は避ける。

### 3. 現代の設計で見直すべき「古い癖」

もし以下のような書き方をしていたら、現代的な手法への切り替えを検討しましょう。

| 古いやり方 (Legacy) | 現代のやり方 (Modern Best Practice) | 理由 |
| :--- | :--- | :--- |
| `float: left;` で横並び | `display: flex;` | clearfixなどの面倒な処理が一切不要。 |
| `display: inline-block;` で横並び | `display: flex;` | HTML上の改行による「謎の隙間」に悩まされない。 |
| `vertical-align` で中央寄せ | `align-items: center;` | 直感的で、あらゆる要素に確実に効く。 |
| `margin-right` で要素間の隙間 | `gap: 20px;` | `last-child` のマージンを消す手間が省ける。 |
| `width: 100%` + `px`のマージン | `width: auto;` または `flex: 1;` | 計算ミスによる横スクロール発生を防ぐ。 |

---

### 4. 整理・設計のベストプラクティス（初期から癖付けること）

#### 1. ボックスモデルの統一
プロジェクトの最初に必ずこれを書く。
```css
*, *::before, *::after {
  box-sizing: border-box;
}
```

#### 2. レイアウトの「外」と「内」を分ける
*   **外側の距離:** `margin` または `gap`（親が制御する）。
*   **内側の余白:** `padding`（自分自身の内側を守る）。
*   **癖付け:** 要素自身に `margin` を持たせすぎない。親要素が `gap` で子要素同士の距離をコントロールする方が、コンポーネントの再利用性が高まります。

#### 3. 魔法の数字「Magic Number」を避ける
*   `top: 13px;` や `left: 4px;` のような、**「なんとなく見た目で合わせた中途半端な数字」**を使わない。
*   なぜその数字なのか説明できない配置は、画面幅が変わった時に必ず崩れます。`flex` や `center` で論理的に配置しましょう。

#### 4. CSS変数の活用
色だけでなく、配置に関わる数値も変数化する癖をつける。
```css
:root {
  --main-padding: 20px;
  --header-height: 60px;
  --z-index-header: 100;
}
```
