CSSの核心である「カスケード（Cascade）」「詳細度（Specificity）」「継承（Inheritance）」について。
これらは、**「複数のスタイル定義がぶつかったとき、最終的にどの値が採用されるのか？」**というルールを決めるための仕組みです。ここを理解していないと、「書いたのに反映されない！」「なぜか意図しない色になる」といったことが起きます。

---

### 1. カスケード (Cascade)：「上から下への流れ」

カスケードとは、スタイルシートが「上から下へ」読み込まれ、**後から書かれたものが優先される**という基本的なルールです。

#### 具体例：同じ強さのルールが並んだ場合
```css
/* (A) */
h1 {
  color: red;
}

/* (B) */
h1 {
  color: blue;
}
```
*   **結果:** `h1` は **青色 (blue)** になります。
*   **理由:** セレクター（`h1`）の強さが同じ場合、CSSファイルの中でより**後に記述されたもの**が優先されます。

#### 実務でのポイント
*   ボタンの基本スタイルを上に書き、その下に「特定のページ用の上書き」を書くのはこのためです。基本スタイル⇒詳細スタイル
*   外部ライブラリ（Bootstrapなど）を読み込む際は、自分のCSSを後に読み込まないと上書きできません。

---

### 2. 詳細度 (Specificity)：「セレクターの強さ」

カスケード（記述順）よりも強力なのが「詳細度」です。**より具体的なセレクターほど優先度が高くなります。**

詳細度は「点数」で考えると理解しやすいです。MDNに基づいた4つの階層で計算します。

#### 点数の計算ルール (0, 0, 0)
1.  **IDセレクター** (`#my-id`): 100点
2.  **クラスセレクター / 属性セレクター / 擬似クラス** (`.my-class`, `[type="text"]`, `:hover`): 10点
3.  **要素セレクター / 擬似要素** (`h1`, `div`, `::before`): 1点

#### 具体例で比較
以下の3つのルールが同じ要素（`<h1 id="title" class="main-title">`）を指しているとします。

```css
/* (A) 要素セレクターのみ：1点 */
h1 {
  color: blue;
}

/* (B) クラスセレクター：10点 */
.main-title {
  color: green;
}

/* (C) IDセレクター：100点 */
#title {
  color: red;
}
```

*   **結果:** **赤色 (red)** になります。
*   **理由:** (C)が100点、(B)が10点、(A)が1点なので、(C)が圧倒的に勝利します。記述の順番が (C)→(B)→(A) と逆になっていても、IDセレクターが勝ちます。

#### 複雑な組み合わせの例
```css
/* (D) 10点 + 1点 = 11点 */
.main-title h1 {
  color: orange;
}

/* (E) 10点 + 10点 = 20点 */
.header .main-title {
  color: purple;
}
```
*   **結果:** より合計点が高い (E) が優先されます。

#### 【重要】現代のベストプラクティス
現代のCSS設計では、「**IDセレクターでスタイルを書かない**」のが定石です。IDを使うと詳細度が高くなりすぎてしまい、後から上書きするのが非常に困難になるからです。
基本的に**クラス（.class）をベースに設計する**ことで、詳細度をフラットに保つのが良いです。

### 3. 継承 (Inheritance)：「親から子への受け継ぎ」

継承とは、ある要素に設定したスタイルが、その中にある子要素にも自動的に適用される仕組みです。

#### 継承されるプロパティの例（文字に関するものが多い）
*   `color`
*   `font-family` / `font-size`
*   `line-height`
*   `text-align`

#### 継承されないプロパティの例（箱の形に関するものが多い）
*   `width` / `height`
*   `margin` / `padding` / `border`
*   `background`

#### 具体例で比較
```html
<div class="parent">
  <p>私は子要素です</p>
</div>
```

```css
.parent {
  color: blue;          /* 継承される */
  border: 1px solid black; /* 継承されない */
}
```
*   **結果:**
    *   `p` タグの中の文字は **青色** になります（親の `color` を継承したため）。
    *   `p` タグに **枠線 (border) はつきません**（`border` は継承されないため）。

#### 制御するためのキーワード
「継承したい（またはしたくない）」ときに使える特別な値があります。
*   `inherit`: 親要素の値を強制的に継承する。
    *   例: `button { color: inherit; }` と書くと、ボタン特有の色を無視して親の文字色と同じになります。
*   `initial`: ブラウザの初期値（デフォルト）に戻す。
*   `unset`: 継承されるプロパティなら継承し、されないなら初期値に戻す（自然な状態にする）。

---

### 4. 特殊ルール：!important (最終兵器)

どのルールよりも（詳細度やカスケードを無視して）最優先させる方法があります。

```css
p {
  color: red !important;
}
```

*   **注意点:** `!important` はカスケードの仕組みを破壊するため、**「禁じ手」**に近い扱いです。
*   **いつ使うか:** 外部ライブラリのスタイルをどうしても上書きできない場合などの、最終手段としてのみ使います。

---

### まとめ：優先順位のフローチャート

ブラウザがスタイルを決定する際、以下の優先順位でチェックします。

1.  **`!important` が付いているか？**（あれば最強）
2.  **詳細度が高いのはどれか？**（ID > クラス > 要素）
3.  **記述順が後なのはどれか？**（同じ詳細度なら下にある方が勝ち）
4.  **親から継承したスタイルか？**（自分で直接指定したスタイルの方が常に継承より強い）

#### 初心者が癖付けるべき習慣
*   **IDを使わずクラスで書く:** 詳細度のカオスを防ぐ。
*   **関連するスタイルは近くにまとめる:** カスケード（記述順）を把握しやすくする。
*   **CSS変数を使う:** `color: var(--main-color);` のように書くことで、一箇所変えるだけで全体に反映でき、カスケードの悩みも減ります。

この3つの概念を理解していれば、CSSの挙動の予測がつくようになり、デバッグ（修正）のスピードが格段に上がります。
