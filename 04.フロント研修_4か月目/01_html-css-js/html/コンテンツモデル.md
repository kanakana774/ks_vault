HTMLの**コンテンツモデル（Content Model）**とは、**「<span style="background:#fdbfff">どの要素の中に、どのカテゴリの要素を入れてもよいか</span>」という入れ子のルール**のことです。

HTML4までは「ブロックレベル要素」と「インライン要素」という単純な分類でしたが、現在のHTML（HTML Living Standard）では、要素の役割に基づいてより詳細な**7つの主要カテゴリ**に分類されています。

以下にコンテンツモデルの主要なポイントをまとめます。

---

### 1. 7つの主要カテゴリ
ほとんどのHTML要素は、以下の7つのカテゴリのいずれか（または複数）に属しています。

| カテゴリ名 | 概要 | 主な要素 |
| :--- | :--- | :--- |
| **メタデータ** (Metadata) | 文書の情報の定義や、他の文書との関係を指定する。 | `<link>`, `<meta>`, `<script>`, `<style>`, `<title>` |
| **フロー** (Flow) | 文書のボディ内で使用されるほとんどの要素。 | `<div>`, `<p>`, `<a>`, `<span>`, `<section>`, `<img>` など多数 |
| **セクショニング** (Sectioning) | 文書の構造（章、節など）を定義し、アウトラインを作成する。 | `<article>`, `<aside>`, `<nav>`, `<section>` |
| **ヘッディング** (Heading) | セクションの見出し。 | `<h1>`〜`<h6>`, `<hgroup>` |
| **フレージング** (Phrasing) | 文書内のテキストおよびテキスト内のマークアップ。 | `<span>`, `<strong>`, `<a>`, `<img>`, `<br>` |
| **エンベディッド** (Embedded) | 文書内に他のリソース（画像、動画など）を埋め込む。 | `<img>`, `<iframe>`, `<video>`, `<canvas>`, `<svg>` |
| **インタラクティブ** (Interactive) | ユーザーが操作（クリック、入力など）できる。 | `<a>`, `<button>`, `<input>`, `<select>`, `<textarea>` |

---

### 2. 特殊なモデル
特定の要素には、上記以外の特殊なルールが適用されます。

*   **トランスペアレント（Transparent：透過的）**
    *   自身が属する親要素のコンテンツモデルをそのまま引き継ぐものです。
    *   例：`<a>`, `<ins>`, `<del>`, `<canvas>`
    *   *例：`<div>`（フロー）の中の`<a>`はフロー要素を入れられますが、`<p>`（フレージングのみ）の中の`<a>`にはフレージング要素しか入れられません。*
*   **パルパブル（Palpable：明白な）**
    *   隠れていないコンテンツを少なくとも1つ持っている必要がある要素です。空の状態が推奨されない要素などが該当します。
*   **スクリプトサポート（Script-supporting）**
    *   ユーザーには表示されないが、スクリプトのために存在する要素。
    *   例：`<script>`, `<template>`

---

### 3. なぜコンテンツモデルが重要か？
1.  **正しいアウトラインの形成**: 検索エンジン（SEO）やスクリーンリーダーが文書の構造を正しく理解できるようになります。
2.  **表示の安定性**: ルールに反した入れ子（例：`<p>`の中に`<div>`を入れるなど）をすると、ブラウザが自動補正を行ってしまい、意図しない表示崩れの原因になります。
3.  **メンテナンス性**: 共通のルールに従うことで、コードの品質が保たれ、複数人での開発がスムーズになります。

---

### 4. 昔の「ブロックレベル・インライン」との違い
かつては「ブロックレベル＝改行される」「インライン＝改行されない」という見た目に基づいた分類でしたが、現在は**「要素の意味や役割」**に基づいた分類に変わりました。

*   **昔**: `<a>`（インライン）の中に`<div>`（ブロック）を入れるのはNG。
*   **今**: `<a>`はトランスペアレントなので、親が許可していれば中に`<div>`を入れてもOK。

### まとめ：調べ方のコツ
「このタグの中に何を入れていいんだっけ？」と迷ったときは、[MDN Web Docs](https://developer.mozilla.org/ja/) などで各要素の「許可されている内容（Content model）」の項目を確認するのが最も確実です。


---

実務でHTMLコーディングを行う際に、特に間違いやすく、かつ重要度の高いコンテンツモデルのルールを「具体例」と「アンチパターン（やってはいけない例）」に分けて整理しました。

---

### 1. 段落要素（`<p>`）の制限
最も頻出するミスの一つです。`<p>`は「フレージングコンテンツ」しか持てません。

*   **⭕️ 正解（OK）**: テキスト、`<span>`、`<strong>`、`<a>`、`<img>`、`<br>`
*   **❌ アンチパターン**:
    *   `<p><div>...</div></p>` （ブロックレベル的な要素はNG）
    *   `<p><ul>...</ul></p>` （リストもNG）
    *   `<p><h1>...</h1></p>` （見出しもNG）
*   **⚠️ 実務上の注意**: `<p>`の中に`<div>`を書くと、ブラウザが「`<p>`が閉じられた」と自動解釈し、DOM構造が勝手に分割されます。

---

### 2. 透過的（Transparent）な要素：`<a>`
`<a>`タグは、**「親要素のコンテンツモデルを継承する」**という特殊な性質を持ちます。

*   **⭕️ 正解（OK）**:
    *   `<div><a href="..."><div>カード全体</div></a></div>`
    *   HTML5以降、`<a>`でブロック要素を囲むことは正当な仕様です（バナー全体をリンクにする場合など）。
*   **❌ アンチパターン**:
    *   `<a><a href="...">...</a></a>` （**aの入れ子は絶対NG**）
    *   `<a><button>...</button></a>` （**インタラクティブ要素の入れ子はNG**）
*   **⚠️ 実務上の注意**: カード全体を`<a>`で囲む際、その中に「詳細はこちら」のような別の`<a>`や`<button>`を配置することはできません。

---

### 3. インタラクティブ要素の重複禁止
ユーザーが操作する要素の中に、別の操作要素を入れることはできません。

*   **❌ アンチパターン**:
    *   `<button><input type="checkbox"></button>`
    *   `<button><a href="...">...</a></button>`
    *   `<label><a href="...">利用規約</a>に同意する</label>`（※厳密にはエラーではないが、クリック判定が競合するため避けるべき）
*   **⚠️ 実務上の注意**: ボタンの中にリンクを置きたい場合は、CSSでボタンのように見せた`<a>`タグを一つ置くのが正解です。

---

### 4. リスト要素（`<ul>`, `<ol>`, `<dl>`）
直下に入れられる要素が厳格に決まっています。

*   **⭕️ 正解（OK）**:
    *   `<ul>` や `<ol>` の直下は `<li>` または `<script>`, `<template>` のみ。
    *   `<dl>` の直下は `<dt>`, `<dd>` または `<div>` (※HTML5.2以降OKになった)。
*   **❌ アンチパターン**:
    *   `<ul><div>...</div></ul>` （**divを直下に入れるのはNG**）
    *   `<ul><a href="..."><li>...</li></a></ul>` （**aをliの外側にするのはNG**）
*   **⚠️ 実務上の注意**: リスト全体をリンクにしたい場合は、`<li>` の**中**に `<a>` を入れ、その `<a>` を `display: block;` にします。

---

### 5. 見出し要素（`<h1>`〜`<h6>`）
見出しも`<p>`と同様、フレージングコンテンツのみを許可します。

*   **⭕️ 正解（OK）**: `<h1><span>タイトル</span>副題</h1>`
*   **❌ アンチパターン**:
    *   `<h1><div>...</div></h1>`
    *   `<h1><p>...</p></h1>`
*   **⚠️ 実務上の注意**: ロゴ画像を`<h1>`に入れるのはOKですが（`<img>`はフレージングなので）、構造的なレイアウトを組もうとして`<div>`を混ぜないよう注意してください。

---

### 6. セクショニング要素（`<header>`, `<footer>`, `<address>`）
これらは「どこにでも置ける」わけではありません。

*   **❌ アンチパターン**:
    *   `<header><header>...</header></header>` （header/footerの入れ子はNG）
    *   `<address><section>...</section></address>` （addressの中にセクショニング要素や見出しはNG）
    *   `<footer><header>...</header></footer>` （footerの中にheaderを入れるのはNG）

---

### 7. フォーム関連（`<label>`, `<button>`）
*   **❌ アンチパターン**:
    *   `<label for="name"> 名前：<input id="name"> <input id="age"> </label>`
    *   （**1つのlabelの中に、2つ以上のフォーム要素（ラベル付け可能要素）を入れてはいけない**）
*   **⭕️ 正解（OK）**: 1つのlabelに対し、対応するinputは1つだけ。

---

### 8. 表要素（`<table>`）
直下に入れられる順番が決まっています。

*   **⭕️ 正解（正しい順序）**:
    1.  `<caption>`（任意）
    2.  `<colgroup>`（任意）
    3.  `<thead>`（任意）
    4.  `<tbody>` または `<tr>`
    5.  `<tfoot>`（任意）
*   **❌ アンチパターン**: `<table><div>...</div></table>`
*   **⚠️ 実務上の注意**: `<table>`の直下に`<div>`は置けません。ラッパーが必要な場合は、`<table>`全体を`<div>`で囲みます。

---

### 実務での「全量チェック」に役立つ判断フロー

1.  **「これは文字の代わりか？」**
    → はい：**フレージングコンテンツ**（`<span>`, `<img>`, `<a>`など）。`<p>`や`<h1>`に入れてOK。
2.  **「これは箱（レイアウト）か？」**
    → はい：**フローコンテンツ**（`<div>`, `<section>`, `<ul>`など）。`<p>`や`<h1>`に入れてはダメ。
3.  **「これはクリックできるか？」**
    → はい：**インタラクティブコンテンツ**。`<a>`や`<button>`の中にさらに入れてはダメ。
4.  **「特殊な親はいないか？」**
    → `<ul>`, `<ol>`, `<dl>`, `<table>`などは、直下に入れられる子が法律で決まっている。

### 迷った時のツール
*   **[W3C Markup Validation Service](https://validator.w3.org/)**: 自分の書いたHTMLを貼り付けると、コンテンツモデル違反をすべてエラーとして指摘してくれます。実務の最終確認にはこれが最強です。


---

`<div>` は「意味を持たない無色透明な箱」なので、レイアウト目的で多用してしまう（いわゆる **Divitis / div病**）のは実務でもよくある悩みです。

`<div>` を適切なタグに置き換えるための**「3つの視点」**と、**具体的ビフォーアフター**をまとめました。

---

### 1. 「文書の大きな枠組み」を意識する
ページ全体をいくつかの大きな塊（ランドマーク）に分ける際、`<div>` を使うのは避けましょう。

*   **意識すること**: 「ここはヘッダーか？ メインか？ フッターか？」
*   **使うタグ**: `<header>`, `<main>`, `<footer>`, `<nav>`, `<aside>`

#### 【具体例】
*   **❌ アンチパターン (divだらけ)**
    ```html
    <div class="header">...</div>
    <div class="content">
      <div class="side-menu">...</div>
      <div class="main-article">...</div>
    </div>
    <div class="footer">...</div>
    ```
*   **⭕️ 改善後 (意味が明確)**
    ```html
    <header>...</header>
    <div class="content-wrapper"> <!-- レイアウト用のdivはOK -->
      <aside>...</aside> <!-- 補足情報・サイドナビ -->
      <main>...</main> <!-- メインコンテンツ -->
    </div>
    <footer>...</footer>
    ```

---

### 2. 「コンテンツの種類」で使い分ける
中身が「独立した記事」なのか「単なる区切り」なのかで使い分けます。

*   **意識すること**: 「その塊は、単体で別のサイトに持って行っても意味が通じるか？」
*   **使うタグ**: `<article>`, `<section>`, `<figure>`

#### 【具体例：ブログのカードUI】
*   **❌ アンチパターン**
    ```html
    <div class="card">
      <div class="image-box"><img src="..."></div>
      <div class="title">記事のタイトル</div>
      <div class="desc">記事の概要テキスト...</div>
    </div>
    ```
*   **⭕️ 改善後**
    ```html
    <article class="card"> <!-- 独立した一つの記事単位 -->
      <figure> <!-- 図版（画像＋キャプション）のセット -->
        <img src="...">
      </figure>
      <h3>記事のタイトル</h3> <!-- タイトルなら見出しタグ -->
      <p>記事の概要テキスト...</p> <!-- 文章ならpタグ -->
    </article>
    ```

---

### 3. 「リスト（箇条書き）」ではないか検討する
同じような構造の要素が並んでいる場合、それは `<ul>` や `<dl>` であるべきケースが非常に多いです。

*   **意識すること**: 「これは項目の並び（リスト）か？」「名前と値のセットか？」
*   **使うタグ**: `<ul>`, `<li>`, `<dl>`, `<dt>`, `<dd>`

#### 【具体例：会社概要やニュース一覧】
*   **❌ アンチパターン**
    ```html
    <div class="news-list">
      <div class="news-item">2023.10.01：お知らせ１</div>
      <div class="news-item">2023.10.05：お知らせ２</div>
    </div>
    ```
*   **⭕️ 改善後**
    ```html
    <ul class="news-list"> <!-- 箇条書きとして定義 -->
      <li class="news-item"><time datetime="2023-10-01">2023.10.01</time>：お知らせ１</li>
      <li class="news-item"><time datetime="2023-10-05">2023.10.05</time>：お知らせ２</li>
    </ul>
    ```

---

### 「divを使いすぎない」ための判断シート

迷ったときは、以下の優先順位でタグを検討してみてください。

| 状況 | 使うべきタグ |
| :--- | :--- |
| **ナビゲーション（メニュー）** | `<nav>` |
| **独立したコンテンツ（記事・カード）** | `<article>` |
| **文脈上の大きな区切り（章・節）** | `<section>`（※中に必ず見出し`<h2>`等を入れる） |
| **サイドバー・広告・関連リンク** | `<aside>` |
| **画像とキャプションのセット** | `<figure>` と `<figcaption>` |
| **同じ形式の要素が並んでいる** | `<ul>` と `<li>` |
| **用語と説明、ラベルと値のセット** | `<dl>`, `<dt>`, `<dd>` |
| **日付や時間** | `<time>` |

---

### 補足：divを使っていい時、ダメな時

*   **使っていい時（レイアウト目的）**
    *   CSSの `display: flex;` や `grid` を適用させるための「親要素」が必要な時。
    *   背景画像を設定するためだけの「外枠」が必要な時。
    *   **意味を持たせたくない**純粋な装飾目的の時。

*   **避けるべき時（意味がある時）**
    *   その塊に「見出し」を付けたくなる時は、`<section>` や `<article>` にできないか検討してください。
    *   スクリーンリーダー（読み上げソフト）を利用するユーザーにとって、`<div>` だらけのサイトは「どこが重要か」が全く分からない迷路になってしまいます。

**まずは「`<ul>` や `<li>` で代用できないか？」を考えるだけでも、`<div>` の使用量は劇的に減り、構造の綺麗なHTMLになります。**

---

実務で「とりあえず`<div>`」としてしまいがちな箇所を、セマンティック（意味のある）なタグに置き換えるパターンを網羅的にまとめました。

これらを使い分けることで、**SEO（検索エンジン最適化）**、**アクセシビリティ（読み上げソフト対応）**、**コードの可読性**が劇的に向上します。

---

### 1. 文書の大きな構造を作るタグ
ページの骨組みに関する置き換えです。これらは「ランドマーク要素」と呼ばれ、ブラウザや支援技術にページの全体像を伝えます。

| タグ | 説明 |
| :--- | :--- |
| **`<main>`** | ページの主要なメインコンテンツ。1ページに1回だけ使用。 |
| **`<nav>`** | 主要なナビゲーション（メニュー）。 |
| **`<aside>`** | メインとは直接関係ない補足情報（サイドバー、広告など）。 |

#### 【置き換え例】
*   **❌ Before (div)**
    ```html
    <div class="side-bar">...</div>
    <div class="main-content">...</div>
    ```
*   **⭕️ After (Semantic)**
    ```html
    <aside>...</aside>
    <main>...</main>
    ```

---

### 2. コンテンツの塊を定義するタグ
中身の意味に応じて使い分けるタグです。

| タグ | 説明 |
| :--- | :--- |
| **`<article>`** | それ単体で独立したコンテンツ（ブログ記事、ニュース項目、カードUI）。 |
| **`<section>`** | 文脈上の「章」や「節」。**通常、中に見出し（h2-h6）が必要。** |

#### 【置き換え例：お知らせ一覧】
*   **❌ Before (div)**
    ```html
    <div class="news-item">
      <div class="date">2023.10.01</div>
      <div class="text">新商品発売のお知らせ</div>
    </div>
    ```
*   **⭕️ After (Semantic)**
    ```html
    <article class="news-item">
      <time datetime="2023-10-01">2023.10.01</time>
      <h2>新商品発売のお知らせ</h2>
    </article>
    ```

---

### 3. 名前と値（ペア）を表現するタグ
実務で最も「div病」になりやすいのがここです。

| タグ | 説明 |
| :--- | :--- |
| **`<dl>`** | 説明リスト（Definition List）。名前と値のセット全体を囲む。 |
| **`<dt>`** | 名前・項目名（Definition Term）。 |
| **`<dd>`** | 内容・説明（Definition Description）。 |

#### 【置き換え例：会社概要やスペック表】
*   **❌ Before (div)**
    ```html
    <div class="company-info">
      <div class="row">
        <div class="label">会社名</div>
        <div class="value">株式会社サンプル</div>
      </div>
    </div>
    ```
*   **⭕️ After (Semantic)**
    ```html
    <dl class="company-info">
      <div> <!-- dl直下のdivはレイアウト用ならOK -->
        <dt>会社名</dt>
        <dd>株式会社サンプル</dd>
      </div>
    </dl>
    ```

---

### 4. 画像と説明文をセットにするタグ
画像にキャプションを添える場合です。

| タグ | 説明 |
| :--- | :--- |
| **`<figure>`** | 図版、写真、コードブロックなどの自己完結したコンテンツ。 |
| **`<figcaption>`** | `<figure>` の中身に対する説明文（キャプション）。 |

#### 【置き換え例：記事内の画像】
*   **❌ Before (div)**
    ```html
    <div class="photo">
      <img src="mountain.jpg" alt="富士山">
      <div class="caption">夕暮れ時の富士山</div>
    </div>
    ```
*   **⭕️ After (Semantic)**
    ```html
    <figure>
      <img src="mountain.jpg" alt="富士山">
      <figcaption>夕暮れ時の富士山</figcaption>
    </figure>
    ```

---

### 5. ボタンやリンクなどのアクション
「見た目がボタンだから`<div>`にクリックイベントをつける」のは最も避けるべきアンチパターンです。

| タグ | 説明 |
| :--- | :--- |
| **`<button>`** | フォームの送信、モーダルの開閉など「操作」を行う。 |
| **`<a>`** | 別のページや場所への「移動」を行う。 |

#### 【置き換え例：クリック可能な要素】
*   **❌ Before (div)**
    ```html
    <div class="submit-btn" onclick="submit()">送信する</div>
    ```
*   **⭕️ After (Semantic)**
    ```html
    <button type="button" class="submit-btn">送信する</button>
    ```
    *※buttonタグなら、キーボードのEnterやTabキーでの操作にも自動対応します。*

---

### 6. その他の細かい意味づけ
| タグ | 説明 |
| :--- | :--- |
| **`<time>`** | 日付や時間。`datetime`属性でコンピュータが読める形式を指定。 |
| **`<address>`** | 連絡先情報（住所、メール、電話番号など）。 |

### まとめ：置き換えの判断基準

迷ったときは自分にこう問いかけてみてください。

1.  **「これは箇条書きか？」** → `<ul>` / `<li>`
2.  **「これは項目名と中身のセットか？」** → `<dl>` / `<dt>` / `<dd>`
3.  **「これは独立した一つのニュースやカードか？」** → `<article>`
4.  **「これには見出し（hタグ）をつけられるか？」** → `<section>`
5.  **「これは何かを操作するためのものか？」** → `<button>`
6.  **「これは別のページへ飛ぶためのものか？」** → `<a>`

これらすべてに当てはまらず、**「単にCSSで横並びにしたい」「余白を作りたい」という理由だけなら、堂々と `<div>` を使ってOK**です。
