    *   パッケージ側のテーブル構造に合わせてデータを変換し、取り込むなど。
*   **SQLの使われ方：**
    *   **マッピング処理：** `CASE`文を多用するかも。
        *   例：旧DBで性別が「1:男, 2:女」だったものを、新DBの「M:Male, F:Female」に変換して`INSERT`する。

    *   **集計関数：** `COUNT`, `SUM`, `AVG` などの集計はもちろん、期間を絞り込むための複雑な `WHERE` 句を書きます。
    *   **ビュー（VIEW）作成：** 頻繁に使う集計をSQLとして保存しておき、BIツール（グラフ表示ソフト）から呼び出せるようにします。

### 第1問：データ移行タスク
**【シミュレーション】**
旧システムからインポートした `patients` テーブルのデータを、新しいパッケージソフトの「患者管理テーブル（仮に `new_patients`）」に移行します。新しいパッケージには以下の制約があります。
1.  `gender`（性別）は 'M'/'F' ではなく、'1'（男）、'2'（女）に変換すること。
2.  `first_name` と `last_name` を結合して一つの `full_name` カラムに入れること。
3.  住所が空（NULL）の場合は、'住所不明' という文字列を入れること。

#### 解答例と解説
**パターンA：標準的な `CASE` 文と文字列結合**
```sql
INSERT INTO new_patients (patient_id, full_name, gender_code, address)
SELECT 
    id,
    first_name || ' ' || last_name, -- 文字列結合
    CASE 
        WHEN gender = 'M' THEN '1'
        WHEN gender = 'F' THEN '2'
        ELSE '9' 
    END,
    COALESCE(address, '住所不明') -- NULLを置換
FROM patients;
```

*   **優れている点:** `COALESCE` を使ってスマートにNULL処理をしている点。
*   **注意点:** `||` で結合する際、どちらかがNULLだと結果もNULLになるため、名前の欠損があり得る場合は `CONCAT_WS(' ', first_name, last_name)` を使う方が安全です。

### 第2問：病院独自の統計レポートタスク
**【シミュレーション】**
病院の経営層から、「2010年以降に『Diabetes（糖尿病）』と診断（Conditions）された患者の中で、実際に『Metformin』という薬（Medications）を処方された患者の割合を知りたい」という依頼を受けました。まずは該当する「患者ID、氏名、診断名、処方薬名」をリストアップしてください。

#### 解答例と解説
**パターンA：`INNER JOIN` を活用する（一般的）**
```sql
SELECT DISTINCT
    p.id,
    p.first_name || ' ' || p.last_name AS patient_name,
    c.description AS condition_name,
    m.description AS medication_name
FROM patients p
JOIN conditions c ON p.id = c.patient_id
JOIN medications m ON p.id = m.patient_id
WHERE c.description LIKE '%Diabetes%'
  AND m.description LIKE '%Metformin%'
  AND c.start_date >= '2010-01-01';
```

*   **メリット:** 構造が分かりやすく、他の項目（処方日など）も追加しやすい。
*   **デメリット:** `JOIN` によってデータが重複（1人の患者に複数回の処方がある場合など）するため、`DISTINCT` が必須になり、データ量が多いと少し重くなる。

**パターンB：`EXISTS` を活用する（実務で好まれる）**
```sql
SELECT 
    p.id,
    p.first_name || ' ' || p.last_name AS patient_name
FROM patients p
WHERE EXISTS (
    SELECT 1 FROM conditions c 
    WHERE c.patient_id = p.id AND c.description LIKE '%Diabetes%' AND c.start_date >= '2010-01-01'
)
AND EXISTS (
    SELECT 1 FROM medications m 
    WHERE m.patient_id = p.id AND m.description LIKE '%Metformin%'
);
```
*   **メリット:** 「条件に合う人がいるかいないか」だけを判定するため、**実行速度が速い**。また、`DISTINCT` を使わなくても重複が発生しない。
*   **デメリット:** 抽出できる項目が「患者マスタ」にあるものに限定される（薬の具体的な処方日などは出せない）。

### 第3問：マスタの一括修正タスク
**【シミュレーション】**
保守作業の一環です。薬剤マスタ（今回は `medications` テーブル内のデータ）を確認したところ、特定の薬品コード（CODE: '860975'）の名称が、古い「Metformin」のままになっています。これを一斉に「Metformin 500 MG Oral Tablet」に更新してください。ただし、**「過去に一度でも処方された記録があるデータのみ」**を正確に更新する必要があります。

#### 解答例と解説
**パターンA：安全なトランザクションを用いた更新**
```sql
BEGIN; -- 必ずトランザクションを開始

-- 更新前に件数を確認（重要！）
SELECT COUNT(*) FROM medications WHERE code = '860975';

-- 更新実行
UPDATE medications
SET description = 'Metformin 500 MG Oral Tablet'
WHERE code = '860975';

-- 更新後の内容を10件ほど見て確認
SELECT * FROM medications WHERE code = '860975' LIMIT 10;

-- 問題なければ確定
COMMIT; 
-- もし件数がおかしければ
-- ROLLBACK;
```

*   **優れている点:** SESの現場で最も評価される「慎重な」手順。件数確認をしてからコミットする流れ。

**パターンB：サブクエリを使った更新（条件が複雑な場合）**
※もし「特定の受診科で処方されたものだけ変えたい」などの条件がある場合：
```sql
UPDATE medications m
SET description = 'Metformin 500 MG Oral Tablet'
WHERE m.code = '860975'
  AND EXISTS (
      SELECT 1 FROM encounters e 
      WHERE e.id = m.encounter_id 
        AND e.description = 'Wellness Request' -- 例：特定の来院理由のみ
  );
```
*   **メリット:** 関連テーブルの条件を見て更新できる。
*   **デメリット:** `UPDATE` 文の `WHERE` 句にサブクエリを入れると処理が重くなることがあるため、大規模データでは実行計画（EXPLAIN）の確認が必要。
