## 問題 1: 複数の結合と集計

すべての顧客について、それぞれの顧客が注文した商品カテゴリごとの合計注文金額を計算してください。
結果は顧客名、カテゴリ名、合計金額を一覧で表示し、合計金額の降順で並べてください。

### 解答バリエーション

#### バリエーションA: 標準的な結合（JOIN）
```SQL
SELECT
	c.name AS customer_name,
	cat.category_name,
	SUM(oi.quantity * p.price) AS total_amount
FROM
	customers c
	JOIN orders o ON c.customer_id = o.customer_id
	JOIN orderitems oi ON o.order_id = oi.order_id
	JOIN products p ON oi.product_id = p.product_id
	JOIN categories cat ON p.category_id = cat.category_id
GROUP BY
	c.name,
	cat.category_name
ORDER BY
	total_amount DESC;
```

#### バリエーションB: 読みやすさ重視（CTE: 共通テーブル式）
先に注文明細の金額を計算してから、名称を結合する手法です。
```SQL
WITH
	order_details AS (
		SELECT
			o.customer_id,
			p.category_id,
			oi.quantity * p.price AS amount
		FROM
			orders o
			JOIN orderitems oi ON o.order_id = oi.order_id
			JOIN products p ON oi.product_id = p.product_id
	)
SELECT
	c.name AS customer_name,
	cat.category_name,
	SUM(od.amount) AS total_amount
FROM
	order_details od
	JOIN customers c ON od.customer_id = c.customer_id
	JOIN categories cat ON od.category_id = cat.category_id
GROUP BY
	c.name,
	cat.category_name
ORDER BY
	total_amount DESC;
```

### 解説
*   **結合の連鎖:** 顧客(Customers)からカテゴリ(Categories)まで、5つのテーブルを1つのリレーションに繋げる必要があります。
*   **集計関数の適用:** `SUM(数量 * 単価)` によって、行ごとの売上を合計しています。
*   **GROUP BY:** 最終的な出力単位である「顧客名」と「カテゴリ名」の両方を指定する必要があります。
*   **CTE（別解B）のメリット:** 複雑な結合を「計算部分」と「マスター名称結合部分」に切り分けることで、クエリのメンテナンス性が向上します。

## 問題 2: サブクエリと条件指定

レビューの平均評価(rating)が 4.5 を超える商品カテゴリ(category_name)を特定し、そのカテゴリに属する商品の合計在庫数(stock_quantity)を計算してください。

### 解答バリエーション

#### バリエーションA: IN句 + サブクエリ
```SQL
SELECT
	ca.category_id,
	ca.category_name,
	SUM(inv.stock_quantity) AS total_stock
FROM
	categories ca
	INNER JOIN products pr USING (category_id)
	INNER JOIN inventory inv USING (product_id)
WHERE
	ca.category_id IN (
		SELECT
			p.category_id
		FROM
			reviews r
			INNER JOIN products p USING (product_id)
		GROUP BY
			p.category_id
		HAVING
			AVG(r.rating) > 4.5
	)
GROUP BY
	ca.category_id,
	ca.category_name;
```

#### バリエーションB: 結合（JOIN）による集計
```SQL
SELECT
	ca.category_name,
	SUM(inv.stock_quantity) AS total_stock
FROM
	categories ca
	JOIN products pr USING (category_id)
	JOIN inventory inv USING (product_id)
	JOIN (
		-- 平均4.5超のカテゴリIDを抽出
		SELECT
			p.category_id
		FROM
			reviews r
			JOIN products p USING (product_id)
		GROUP BY
			p.category_id
		HAVING
			AVG(r.rating) > 4.5
	) high_rated ON ca.category_id = high_rated.category_id
GROUP BY
	ca.category_name;
```


### 解説
*   **二段階の集計:** 「カテゴリごとの平均評価」という集計結果を条件に、「在庫数の合計」という別の集計を行う問題です。
*   **HAVING句:** `WHERE` 句は個々の行に対するフィルタリングですが、`HAVING` は `GROUP BY` 後の集計結果に対するフィルタリングに使用します。
*   **USING句:** PostgreSQLでは、結合キーの名前が同じ場合 `ON a.id = b.id` の代わりに `USING (id)` と書くことができ、記述を簡潔にできます。普通に結合条件書いても同じです。

## 問題 3: 結合、集計、そしてウィンドウ関数

"各顧客"の"各注文"について、その注文の総額と、その顧客の全注文の平均総額を並べて表示してください。
ヒント: ウィンドウ関数 AVG() を使用します。

### 回答:

```SQL
SELECT
    O.order_id,
    O.customer_id,
    SUM(OI.quantity * P.price) AS order_total,
    AVG(SUM(OI.quantity * P.price)) OVER (PARTITION BY O.customer_id) AS customer_avg_total
FROM Orders AS O
JOIN OrderItems AS OI ON O.order_id = OI.order_id
JOIN Products AS P ON OI.product_id = P.product_id
GROUP BY O.order_id, O.customer_id
ORDER BY O.customer_id, O.order_id;
```

### 解説:

OVER (PARTITION BY ...) を使用して、顧客(customer_id)ごとに注文の総額の平均値を計算しています。SUM() と AVG() を同時に使うことで、各注文の合計と顧客ごとの平均を同時に取得できます。

```SQL
SELECT
    O.order_id,
    O.customer_id,
    SUM(OI.quantity * P.price) AS order_total,
    round(AVG(SUM(OI.quantity * P.price)) OVER (PARTITION BY O.customer_id)) AS customer_avg_total
FROM Orders AS O
JOIN OrderItems AS OI ON O.order_id = OI.order_id
JOIN Products AS P ON OI.product_id = P.product_id
WHERE O.status <> 'Cancelled' -- キャンセル弾くと丁寧
GROUP BY O.order_id, O.customer_id
ORDER BY O.customer_id, O.order_id;
```

## 問題 4: 条件付き集計（PostgreSQL特有の記法含む）

特定の都市(city)に住む顧客による、注文ステータス(status)ごとの注文総数を計算してください。
例えば、「Tokyo」に住む顧客の「Completed」および「Pending」の注文数をそれぞれ表示します。

### 解答バリエーション

#### バリエーションA: 標準SQL（CASE WHEN）
```SQL
SELECT
    cu.city,
    COUNT(CASE WHEN ord.status = 'Pending' THEN 1 END) AS pending_count,
    COUNT(CASE WHEN ord.status = 'Completed' THEN 1 END) AS completed_count
FROM customers cu
JOIN orders ord USING (customer_id)
WHERE cu.city = 'Tokyo'
GROUP BY cu.city;
```

#### バリエーションB: PostgreSQL特有の記法（FILTER句）
```SQL
SELECT
    cu.city,
    COUNT(*) FILTER (WHERE ord.status = 'Pending') AS pending_count,
    COUNT(*) FILTER (WHERE ord.status = 'Completed') AS completed_count
FROM customers cu
JOIN orders ord USING (customer_id)
WHERE cu.city = 'Tokyo'
GROUP BY cu.city;
```

### 解説
*   **縦持ちから横持ちへの変換:** 通常、ステータスごとの件数は `GROUP BY status` で求めますが、それだと結果が複数行（縦）になります。1行（横）に並べるには条件付き集計が必要です。
*   **FILTER句（PostgreSQL 9.4+）:** バリエーションBはPostgreSQL特有の非常に強力な構文です。`CASE WHEN` よりも意図が明確になり、可読性が向上します。
*   **HAVING vs WHERE:** この問題では「Tokyo」という特定の属性で行を絞り込むため、`GROUP BY` の前に動作する `WHERE` 句で絞り込むのが一般的（かつ効率的）です。

## 問題 5: 複雑なサブクエリと HAVING 句

Products テーブル内で、同じ価格(price)を持つ商品が 2 つ以上存在するカテゴリ(category_name)をすべて見つけてください。

### 回答:

```SQL
SELECT
	c.category_name,
	p.price
FROM
	products p
	JOIN categories c ON p.category_id = c.category_id
GROUP BY
	c.category_name, -- どのカテゴリの
	p.price -- どの価格か
HAVING
	COUNT(p.product_id) >= 2 -- その価格の商品が2つ以上あるか
ORDER BY
	c.category_name;
```

```SQL
SELECT
	category_name
FROM
	categories main
WHERE
	EXISTS (
		SELECT
			1
		FROM
			products p
		WHERE
			p.category_id = main.category_id
		GROUP BY
			p.price
		HAVING
			COUNT(p.product_id) >= 2
		);
```
### 解説:

内側のサブクエリで、price でグループ化し、同じ価格を持つ商品の数が 2 つ以上ある価格(price)を取得しています。その結果を使って外側のクエリでカテゴリ名を抽出しています。

## 問題 6: ウィンドウ関数とランキング

各注文(order_id)について、その注文に最も多く含まれる商品のカテゴリ名を表示してください。
同数の場合は、いずれか一つのカテゴリを表示すれば構いません。

### 解答バリエーション

#### バリエーションA: Window関数（ROW_NUMBER）
```SQL
SELECT order_id, category_name
FROM (
    SELECT
        oi.order_id,
        cat.category_name,
        ROW_NUMBER() OVER (PARTITION BY oi.order_id ORDER BY COUNT(*) DESC) as rn
    FROM orderitems oi
    JOIN products p USING (product_id)
    JOIN categories cat USING (category_id)
    GROUP BY oi.order_id, cat.category_name
) t
WHERE rn = 1;
```

#### バリエーションB: PostgreSQL特有の記法（DISTINCT ON）
```SQL
SELECT DISTINCT ON (oi.order_id)
    oi.order_id,
    cat.category_name
FROM orderitems oi
JOIN products p USING (product_id)
JOIN categories cat USING (category_id)
GROUP BY oi.order_id, cat.category_name
ORDER BY oi.order_id, COUNT(*) DESC;
```

### 解説
*   **Top-N分析:** 各注文（グループ）内での最大値を取得する問題です。
*   **ROW_NUMBER:** `PARTITION BY order_id` で注文ごとに区切りを入れ、件数順に番号を振っています。外側で `rn = 1` を指定することで、各注文の1位だけを抽出します。
*   **DISTINCT ON (PostgreSQL特有):** 指定したカラム（order_id）ごとに、`ORDER BY` でソートされた最初の1行だけを返す非常に便利な機能です。サブクエリを回避できるため、PostgreSQLユーザーには好まれます。

```SQL
SELECT
    O.order_id,
    MAX(CASE WHEN T2.rn = 1 THEN T2.category_name ELSE NULL END) AS most_frequent_category
FROM Orders AS O
JOIN (
    SELECT
        OI.order_id,
        Cat.category_name,
        ROW_NUMBER() OVER (PARTITION BY OI.order_id ORDER BY COUNT(OI.product_id) DESC) AS rn
    FROM OrderItems AS OI
    JOIN Products AS P ON OI.product_id = P.product_id
    JOIN Categories AS Cat ON P.category_id = Cat.category_id
    GROUP BY OI.order_id, Cat.category_name
) AS T2 ON O.order_id = T2.order_id
GROUP BY O.order_id
ORDER BY O.order_id;
```

## 問題 7: 存在判定（NOT EXISTS）

各倉庫(Warehouses.warehouse_name)に現在在庫がある商品のうち、まだ一度も注文されていない商品(OrderItems テーブルに存在しない商品)の数を計算してください。

### 解答バリエーション

#### バリエーションA: LEFT JOIN & NULL判定
```SQL
SELECT
    w.warehouse_name,
    COUNT(i.product_id) AS products_not_ordered
FROM inventory i
JOIN warehouses w USING (warehouse_id)
LEFT JOIN orderitems oi USING (product_id)
WHERE i.stock_quantity > 0 AND oi.order_id IS NULL
GROUP BY w.warehouse_name;
```

#### バリエーションB: NOT EXISTS（相関サブクエリ）
```SQL
SELECT
    w.warehouse_name,
    COUNT(*) AS unsold_product_count
FROM warehouses w
JOIN inventory i USING (warehouse_id)
WHERE i.stock_quantity > 0 
  AND NOT EXISTS (
      SELECT 1 FROM orderitems oi WHERE oi.product_id = i.product_id
  )
GROUP BY w.warehouse_name;
```

### 解説
*   **不一致の抽出:** 「AはあるがBにはない」という関係を抽出します。
*   **LEFT JOIN:** 左側のテーブルを基準に残し、右側に一致がなければNULLを入れる特性を利用します。
*   **NOT EXISTS:** 「条件に一致する行が存在しない」ことを判定します。一般的に、データ量が多い場合や結合によって行数が増幅する懸念がある場合は、`LEFT JOIN` よりも `NOT EXISTS` の方が直感的かつ高速な場合があります。

## 問題 8: 階層的な集計

注文を 3 回以上行っており、かつ平均注文金額が $100.00 を超える顧客の ID と名前、および平均注文金額をリストアップしてください。

### 解答バリエーション

#### バリエーションA: サブクエリで「1注文ごとの合計」を算出
```SQL
SELECT
    c.customer_id,
    c.name,
    AVG(order_totals.total_price) AS avg_order_amount
FROM customers c
JOIN (
    -- 1注文あたりの合計金額を算出
    SELECT o.customer_id, o.order_id, SUM(oi.quantity * p.price) AS total_price
    FROM orders o
    JOIN orderitems oi USING (order_id)
    JOIN products p USING (product_id)
    GROUP BY o.customer_id, o.order_id
) order_totals USING (customer_id)
GROUP BY c.customer_id, c.name
HAVING COUNT(order_totals.order_id) >= 3 
   AND AVG(order_totals.total_price) > 100.00;
```

### 解説
*   **集計のレベル（粒度）:** この問題の難しさは、「注文明細（1行1商品）」「注文（1行1決済）」「顧客（1行1人）」という異なる粒度のデータを扱う点にあります。
*   **二段階集計:** 
    1.  まず `orderitems` を `order_id` ごとに集計して「1注文あたりの合計金額」を出す。
    2.  その結果を `customer_id` ごとに集計して「平均」と「回数」を出し、`HAVING` で絞り込む。
*   いきなり `customers` と `orderitems` を結合して `AVG` を取ると、「1商品の価格の平均」になってしまい、正しい「平均注文金額」にならないため注意が必要です。

```SQL
SELECT
	c.customer_id,
	c.name,
	AVG(t2.total_order_amount) AS avg_order_amount
FROM
	customers AS c
	JOIN (
		SELECT
			o.customer_id,
			SUM(oi.quantity * p.price) AS total_order_amount
		FROM
			orders AS o
			JOIN orderitems AS oi ON o.order_id = oi.order_id
			JOIN products AS p ON oi.product_id = p.product_id
		GROUP BY
			o.order_id,
			o.customer_id
	) AS t2 ON c.customer_id = t2.customer_id
GROUP BY
	c.customer_id,
	c.name
HAVING
	COUNT(t2.total_order_amount) >= 3
	AND AVG(t2.total_order_amount) > 100.00;
```

## 問題 9: 全テーブルの総合的な結合と分析

テーブルを適切に結合し、各顧客の会員ランク(rank_name)と、その顧客が支払った合計金額、および合計割引額(合計金額 × 割引率)を計算して表示してください。
結果は、顧客 ID、顧客名、会員ランク、合計支払額、合計割引額を一覧で示してください。

### 回答:

```SQL
SELECT
	c.customer_id,
	c.name AS customer_name,
	m.rank_name,
	SUM(oi.quantity * p.price) AS total_payment,
	ROUND(SUM(oi.quantity * p.price * (m.discount_rate / 100)), 2) AS total_discount
FROM
	customers AS c
	JOIN memberships AS m ON c.membership_id = m.membership_id
	JOIN orders AS o ON c.customer_id = o.customer_id
	JOIN orderitems AS oi ON o.order_id = oi.order_id
	JOIN products AS p ON oi.product_id = p.product_id
GROUP BY
	c.customer_id,
	c.name,
	m.rank_name,
	m.discount_rate
ORDER BY
	c.customer_id;
```

### 解説:

複数の JOIN 文を使って必要なすべてのテーブルを結合し、顧客、会員ランク、支払い、商品情報を統合しています。GROUP BY を適切に使い、顧客ごとの合計金額と合計割引額を計算しています。
