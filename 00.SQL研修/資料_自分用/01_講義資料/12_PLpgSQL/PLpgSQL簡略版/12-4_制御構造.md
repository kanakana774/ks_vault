# PL/pgSQL 実践講座：第4章 制御構造

SQLは「集合」を扱うのが得意ですが、PL/pgSQLの制御構造を使うことで、「特定の条件に合致するデータに対してのみ、一行ずつ異なる複雑なロジックを適用する」といった柔軟な処理が可能になります。


## 4.1 条件分岐：IF と CASE

### 4.1.1 IF 文
最も基本的な条件分岐です。`ELSIF`（`E`がないことに注意）を使って複数の条件を繋げることができます。

**実演：給与ランクの判定ロジック**
```sql
DO $$
DECLARE
    v_emp_id integer := 2; -- Hanako Suzuki
    v_salary numeric;
    v_rank text;
BEGIN
    SELECT salary INTO v_salary FROM employees WHERE emp_id = v_emp_id;

    IF v_salary >= 700000 THEN
        v_rank := 'S Rank';
    ELSIF v_salary >= 600000 THEN
        v_rank := 'A Rank';
    ELSIF v_salary >= 500000 THEN
        v_rank := 'B Rank';
    ELSE
        v_rank := 'C Rank';
    END IF;

    RAISE NOTICE 'Employee ID % (Salary: %) Rank: %', v_emp_id, v_salary, v_rank;
END;
$$ LANGUAGE plpgsql;
```

### 4.1.2 CASE 文
特定の変数の値で分岐させる「単純CASE」と、複雑な条件式を書ける「検索CASE」があります。

**実演：CASE文による部署名の出し分け**
```sql
DO $$
DECLARE
    v_dept_id integer := 2;
    v_dept_category text;
BEGIN
    -- 検索CASE文の例
    v_dept_category := CASE 
        WHEN v_dept_id = 1 THEN 'Profit Center'
        WHEN v_dept_id = 2 THEN 'Technology Center'
        WHEN v_dept_id IN (3, 4) THEN 'Back Office'
        ELSE 'Unknown'
    END;

    RAISE NOTICE 'Dept ID % is categorized as %', v_dept_id, v_dept_category;
END;
$$ LANGUAGE plpgsql;
```

## 4.2 ループの基本：LOOP と EXIT

最も単純な `LOOP` は、明示的に脱出しない限り無限に繰り返されます。

### 4.2.1 EXIT と CONTINUE
*   `EXIT [WHEN condition]`: ループを終了します。
*   `CONTINUE [WHEN condition]`: 以降の処理をスキップして次の回へ進みます。

**実演：基本的なループ制御**
```sql
DO $$
DECLARE
    v_counter integer := 0;
BEGIN
    LOOP
        v_counter := v_counter + 1;
        
        -- 偶数の場合はスキップ
        CONTINUE WHEN v_counter % 2 = 0;
        
        RAISE NOTICE 'Counter: % (Odd only)', v_counter;

        -- 7を超えたら終了
        EXIT WHEN v_counter >= 7;
    END LOOP;
END;
$$ LANGUAGE plpgsql;
```

## 4.3 数値ループ：FOR 文

指定した範囲の数値をカウントアップ（またはダウン）させたい場合に使用します。

**実演：数値指定のループ**
```sql
DO $$
BEGIN
    RAISE NOTICE '--- Normal Step (1 to 5) ---';
    FOR i IN 1..5 LOOP
        RAISE NOTICE 'Value: %', i;
    END LOOP;

    RAISE NOTICE '--- Reverse Step (10 down to 2, step 2) ---';
    FOR i IN REVERSE 10..2 BY 2 LOOP
        RAISE NOTICE 'Value: %', i;
    END LOOP;
END;
$$ LANGUAGE plpgsql;
```

## 4.4 クエリ結果のループ：FOR IN (最重要)

現場のエンジニアが**最も頻繁に使うループ構造**です。SELECTクエリの結果を一行ずつ `RECORD` 変数に格納して処理します。

### 実務でのメリット
*   カーソルを明示的に `OPEN/FETCH/CLOSE` する必要がなく、コードが極めて簡潔になります。
*   一度に全データをメモリに読み込むのではなく、内部的にカーソルを使用して効率的に一行ずつフェッチします。

**実演：全従業員の昇給シミュレーション**
```sql
DO $$
DECLARE
    -- ループ内で使用する行データを保持する変数
    -- RECORD型はどのようなSELECT結果にも対応できる
    r RECORD;
    v_bonus_rate numeric;
BEGIN
    RAISE NOTICE 'Employee Bonus Simulation:';

    -- クエリの結果でループを回す
    FOR r IN (
        SELECT e.name, e.salary, d.dept_name 
        FROM employees e 
        JOIN departments d ON e.dept_id = d.dept_id
        ORDER BY e.salary DESC
    ) 
    LOOP
        -- 部署ごとにボーナス率を変える複雑なロジック
        v_bonus_rate := CASE 
            WHEN r.dept_name = 'Sales' THEN 0.2
            WHEN r.dept_name = 'Engineering' THEN 0.15
            ELSE 0.1
        END;

        RAISE NOTICE 'Name: % (%): Bonus = %', 
            r.name, r.dept_name, (r.salary * v_bonus_rate);
    END LOOP;
END;
$$ LANGUAGE plpgsql;
```

## 4.5 まとめ

1.  **集合演算 (SQL) で済むなら集合演算で済ませよ**: PL/pgSQLのループは強力ですが、単一の `UPDATE` 文などで書ける処理をループで回すのはパフォーマンス上、アンチパターンです。ループは「一行ごとに複雑な外部関数を呼ぶ」「動的な分岐がSQLでは表現しきれない」場合に限定しましょう。
2.  **FOR IN SELECT を優先せよ**: 大量のデータを扱う際、メモリ効率と可読性のバランスが最も良いのが `FOR ... IN (SELECT ...)` です。
3.  **無限ループへの防御策**: `WHILE` や `LOOP` を使う際は、必ず「最大実行回数」や「タイムアウト」を意識するか、脱出条件が確実に満たされるかを確認してください。
4.  **ELSIF の綴りに注意**: プログラミング言語によって `ELSEIF`, `elsif`, `elif` など異なりますが、PostgreSQLは **`ELSIF`** です。
