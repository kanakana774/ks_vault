## 削除と再定義

### 問題1：
テーブル Reviews（商品レビュー）を削除してください
```SQL
DROP TABLE Reviews;
```

### 問題2：
Inventory テーブルの在庫情報をリセットしたい。
ただし テーブル定義（カラムや制約）は残すようにしてください。
```SQL
TRUNCATE TABLE Inventory;
```

### 問題3：
倉庫 Warehouses テーブルを削除したいが、外部キーで Inventory や Staff に参照されています。
依存関係も含めて一括削除してください。
```SQL
DROP TABLE Warehouses CASCADE;
```

### 問題4：
Inventory テーブルに数千件の在庫データが入っている。
一度、すべての在庫をリセットしたい。
DELETE と TRUNCATE のどちらを使えば効率的か？理由も答えてください。

```SQL
TRUNCATE

全件削除に特化しており、高速でログも最小限。
定義は残るため「リセット」に最適。
```

### 問題5：
OrderItems テーブルから、product_id = 1001 の商品に関するデータを削除したい。
DELETE と TRUNCATE のどちらを使うべきか？理由も答えてください。

```SQL
DELETE

条件付き削除ができるのは DELETE。
TRUNCATE は全件削除しかできない。
```

### 問題6：
Payments テーブルを Orders に外部キーで参照している場合において、Orders のデータを一括削除したい。
DELETE と TRUNCATE のどちらを使うべきか？理由も答えてください。

```SQL
DELETE	
	
TRUNCATE は外部キー制約があると基本的に使えない（エラーになる）。	
DELETE なら外部キーを考慮しながら削除可能。	
```

### 問題7：
在庫管理システムの Inventory テーブルには AUTO_INCREMENT の id カラムがある。
このテーブルを一度空にしたあと、新しいデータを入れる際に idを1から再スタートさせたい。
DELETE と TRUNCATE のどちらを使うべきか？理由も答えてください。

```SQL
TRUNCATE

テーブルが一度 ドロップ＆再作成 に近い動作をするので、
AUTO_INCREMENT カウンタは リセットされ、1から再スタートする。

```

## 構造変更
### 問題1：
Customers テーブルに「生年月日」を管理するカラム birth_date（DATE型）を追加してください。

```SQL
ALTER TABLE 		
	Customers

	birth_date DATE;	
```

Products テーブルの price を整数型（INT）に変更してください。

```SQL
ALTER TABLE 		
	Products

	price TYPE INT;	
```

### 問題3：
Customers テーブルのカラム phone を削除してください。

```SQL
ALTER TABLE 		
	Customers

	phone;	

```

Staff テーブルのカラム position を job_title に名前変更してください。

```SQL
ALTER TABLE
```

Orders テーブルの status 列に、デフォルト値 'Pending' を設定してください。

```SQL

```

### 問題6：
Payments テーブルの method に チェック制約 を追加し、
支払い方法が 'Credit Card', 'BankTransfer', 'Cash' のいずれかのみ登録できるようにしてください。

```SQL
ALTER TABLE 	
	Payments
ADD CONSTRAINT 	
	chk_payment_method
CHECK (method IN ('Credit Card', 'BankTransfer', 'Cash'));	
```


### 問題8：

Shipments テーブルを以下のように変更しましょう。
PKであるshipment_idのカラムの削除
order_id, shipped_date の組み合わせが一意になるように主キー制約を追加

```SQL
ALTER TABLE shipments
DROP COLUMN shipment_id;

ALTER TABLE shipments
ADD CONSTRAINT pk_shipments PRIMARY KEY (order_id, shipped_date);
```

### 問題9：
Customers テーブルで membership_id を 必須（NOT NULL） にしたい。
ただし既に NULL が入っている行があるため、以下の手順で操作を行ってください。
Membershipsテーブルにmembership_idを999として「仮のランク（General）」を追加
Customers テーブルのmembership_idがNULLのデータを仮のランクで更新
Customers テーブルのmembership_id を 必須に変更

```SQL
-- ① 仮ランクを追加						
INSERT INTO Memberships (membership_id, rank_name, discount_rate)						
VALUES (999, 'General', 0.00);						
	
-- ② NULLを仮ランクに更新						
UPDATE Customers						
SET membership_id = 999						
WHERE membership_id IS NULL;						

-- ③ NOT NULL制約を付与						
ALTER TABLE Customers						
ALTER COLUMN membership_id SET NOT NULL;						
```
