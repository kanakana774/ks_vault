## 0. 前提：現状はかなり網羅されている

漏れの指摘に入る前に、**すでに厚い**ところを確認しておく（重複して足さないため）。

DDL・制約・データ型・正規化・マスタ/トラン／CRUD・演算子・NULL・LIKE（ILIKE・エスケープ）・BETWEENの半開区間・LIMIT/OFFSETのタイブレーク／文字列・日付関数・`||`と`CONCAT`のNULL差・不可視空白／CASE式（WHEN順序・シンプルCASEとNULL・SET句のELSE省略）／集約・GROUP BY・HAVING・`COUNT(*)`と`COUNT(列)`・整数除算・論理実行順・年月キーの作り方／JOIN全種・ON句とWHERE句・非等価結合（適用期間）・LEFT JOINを殺すINNER JOIN・行の増殖と集計不整合・ER図からの経路選択／集合演算子／サブクエリ（非相関・相関・EXISTS・スカラ）・IN と EXISTS・書き換え／ウィンドウ関数・CTE・view・sequence／PL/pgSQL 全8章／トランザクション・ACID・分離レベル・MVCC・`FOR UPDATE`・デッドロック・ロック調査／index・EXPLAIN・スキャン方式・結合アルゴリズム・効かない落とし穴・統計情報／psqlチートシート／実務想定問題（障害調査・データ移行・夜間バッチ・整合性チェック・帳票）。

## A. 優先度【高】— 実務で必ず触るのに、講義に無い

### A-1. 更新系SQLの実務パターンが講義に存在しない

現行の CRUD 講義（[[02_CRUDについて]]）は単一テーブルの `INSERT` / `UPDATE` / `DELETE` で終わっている。実務のタスク例「条件に合致する顧客情報の一括更新」「システム間データ変換・登録処理」で使うのは全部この先。

- [ ] **`INSERT ... SELECT`** — 講義に0件。データ移行・作業退避・サマリテーブル作成の基本形
- [ ] **`UPDATE ... FROM`（結合更新）** — 講義に0件。**なのに [[業務システムを意識した問題_回答付]] の問題3（顧客ランク一括付与）で書かせている**＝教えずに出題している状態
- [ ] **`DELETE ... USING`（結合削除）** — 0件
- [ ] **`CREATE TABLE AS SELECT` / `CREATE TEMP TABLE`** — 講義に0件。「消す前に退避」「バッチの中間結果」の定番。破壊的操作の作法としても効く
- [ ] **`RETURNING`** — 素のSQLとしては無し（[[12-3_SQLの実行と結果の取得]] の PL/pgSQL 文脈のみ）
- [ ] **UPSERT `INSERT ... ON CONFLICT`** — PL/pgSQL章（12-3・12-8）にしかない。素のSQLとして未紹介。マスタ同期・再実行可能バッチの定番で、[[SQL学習トピックの選定]] でもステージ5に「MERGE（UPSERT）」として挙げていた

→ 置き場案: `01_講義資料/03_更新系SQLの実務パターン.md` を新設（02章と11章の間）。演習は `02_問題/03_UPDATE文について` の追加問題に寄せる手もある。

### A-2. `SELECT DISTINCT` を正面から扱った節が無い

`COUNT(DISTINCT 列)`（[[07_集約関数]]）と解答例中の使用だけで、**講義本編・用語集ともに `SELECT DISTINCT` の節が無い**。

- [ ] 現場で最初に覚え、かつ最初に誤用する構文（「重複が出たからDISTINCTで消す」で原因を隠す）。[[08_補足_結合]] §6（行の増殖）と**対で**教えると、なぜ増えたかを考える癖に繋がる

### A-3. 「無い方を探す」＝アンチジョインの定型化と `NOT IN` の罠

障害調査（孤児レコード検出・件数突合）の中核だが、整理された形で存在しない。

- [ ] **`NOT EXISTS` / `LEFT JOIN ... WHERE 右.PK IS NULL` / `EXCEPT` の3通り**を並べた節が無い（`LEFT JOIN`＋`IS NULL` は [[08_補足_結合]] に1箇所出てくるだけ、`EXCEPT` は [[00_SQL研修/02_問題/09_集合演算子]] にあるが「差分を出す道具」としての実務接続が薄い）
- [ ] **`NOT IN` + サブクエリ + NULL で結果が全件消える罠** — 記述0件。[[02_演算子]] は `NOT IN (...)` を「`<>` の AND と等価」と説明して終わっており、[[00_SQL研修/02_問題/10_サブクエリ]] の IN/EXISTS 比較も性能の話に寄っている。**実務で最も痛く、最も気づきにくいバグの一つ**

### A-4. 数値関数と丸めの節が無い

[[00_SQL研修/02_問題/04_関数]] は「文字列関数／日付・時刻関数／汎用関数」の3本立てで、**数値関数の節が存在しない**。

- [ ] `ROUND` / `TRUNC` / `CEIL` / `FLOOR`、`ROUND(値, 桁数)` が `numeric` にしか使えないこと、`::numeric` へのキャスト、消費税・按分の丸め
- [ ] [[01_データ型]] は「金額に FLOAT を使うな」と明記できているので、**その受け皿が関数側に無い**状態。帳票・金額計算は「1円の誤差も許されない」領域（[[★SQLの現場で求められる人材想定★]] #2）
- [ ] 整数除算の罠自体は [[00_SQL研修/02_問題/07_group byと集計関数]] 問題11でカバー済み＝**演習だけ先にある**

### A-5. `date_trunc` と月初・月末の計算

- [ ] `date_trunc` は教材全体で**0件**。月次集計の軸は現在 `TO_CHAR(日付,'YYYY-MM')`（＝文字列）で教えている（[[00_SQL研修/02_問題/04_関数]] 問題14・[[00_SQL研修/02_問題/07_group byと集計関数]] 問題17）。年跨ぎの罠を潰す教え方として優れているが、**文字列キーのままでは期間比較・前月との差・日付型で返す帳票で詰まる**
- [ ] 月初・月末の作り方（`date_trunc('month', d)`、`+ INTERVAL '1 month' - INTERVAL '1 day'`）と、半開区間（`>= 月初 AND < 翌月初`）の組み合わせ。半開区間は [[00_SQL研修/02_問題/06_SELECT文（特殊な演算子）]] 問題14で扱っているので**接続するだけ**

### A-6. 既存DBの構造をSQLで調べる手段

- [ ] `information_schema` / `pg_catalog` が**0件**。`\d` 系は [[99_補足_psqlコマンドチートシート]] にあるが **psql 専用**で、現場の道具（A5M2 / DBeaver / SQL Developer / SSMS）では使えない
- [ ] 保守・改修案件の初日にやるのは「テーブル定義・制約・外部キー・インデックスを調べる」。`information_schema.columns` / `information_schema.table_constraints` / `pg_indexes` の3本だけでも実務直結

### A-7. 書いたSQLを自分で検証する作法が講義に無い（構文ではなく手順の漏れ）

[[★SQLの現場で求められる人材想定★]] §3-1 で追加。**構文の網羅では出てこない種類の漏れ**なので、この章の他項目とは性格が違う。

- [ ] 「更新前に同じ `WHERE` で `SELECT` して件数を見る → `BEGIN` で囲む → 件数を照合して `COMMIT`」という作法が、**実務想定問題の解説の中だけ**に存在する。[[業務システムを意識した問題_回答付]] 問題3の講師向け解説に「この『事前検証』プロセスを**研修で徹底させます**」と書いてあるが、それを教える教材が無い
- [ ] 実務想定問題は最後にやる発展問題なので、**そこまで到達しない研修生には一度も伝わらない**
- [ ] 資質「正確性と品質」（1円の誤差も許されない領域）の中核。置き場案は `01_講義資料/00_SQLを検証する.md`（[[00_SQLを書く時の注意]] の隣＝書き方の作法と検証の作法の対）。A-1 の `CREATE TABLE AS SELECT`（退避）と [[15-1_導入_トランザクションとACID]] に接続する

## B. 優先度【中】— あると配属後の立ち上がりが変わる

### B-1. 既存の長いSQLを「読む」演習が無い

- [ ] [[★常駐先の想定業務★]] に「新規開発よりも保守・改修・運用対応が中心」「既存SQLの解析・修正・チューニングの比率が高い」と書いてあるのに、**演習は全部「書く」側**
- [ ] 土台の資料（[[07_補足_groupByの論理実行順]]・[[10_補足_相関サブクエリの読み方]]）は揃っているので、「100行のSQLを渡して日本語で説明させる／条件を1つ足させる／なぜこの結果になるか説明させる」型の演習を作る余地がある

### B-2. 権限とロール（`GRANT` / `REVOKE`）

- [ ] 教材中の出現は [[SQL学習トピックの選定]] の「ステージ7＝絶対やらない」の1件のみ
- [ ] ただし現場では「参照権限しかない」「本番はSELECTのみ」「見えないのは権限のせい」に**必ず**当たる。設計として教える必要はなく、**トラブルの語彙として15分**でよい

### B-3. Oracle / SQL Server の方言差

- [ ] [[★常駐先の想定業務★]] 自身が「Java + Oracle + PL/SQL が今でも主流」「PL/SQL・T-SQLへの学習意欲を見せることが重要」と書いているのに、教材は PostgreSQL 一本
- [ ] [[01_データ型]] に「他RDBMSでの類似型」列はある＝**型だけは対応済み**。関数・構文の対応表が無い（`NVL`↔`COALESCE`、`DECODE`↔`CASE`、`SYSDATE`↔`NOW()`、`ROWNUM`/`FETCH FIRST`↔`LIMIT`、`(+)`↔`OUTER JOIN`、`TO_DATE` の書式、`DUAL`）
- [ ] 1ページの対応表だけで面接・配属直後の効果が大きい。**新規に教えるのではなく既存知識の翻訳表**なので工数は小さい

### B-4. マテリアライズドビュー

- [ ] `CREATE MATERIALIZED VIEW` は0件（CTEの内部マテリアライズの言及が [[99_補足_CTE（共通テーブル式）]] に1件だけ）
- [ ] [[99_補足_viewについて]] は更新可能ビューまで扱えているので、**帳票・集計スナップショットとしてのマテビューと `REFRESH`** を足すだけ。夜間バッチで集計テーブルを作る話とも繋がる

### B-5. トリガー・カーソル・動的SQL が PL/pgSQL 詳細版にしか無い

- [ ] [[12-7_高度なトピック]]（詳細版）のみ。**簡略版（12-1〜12-6）で回すと未接触**になる
- [ ] とくに**トリガー**は「知らないと調査で詰む」種類の知識（更新した覚えのない列が変わる／INSERTしたら別テーブルにも入る）。簡略版に「存在と調べ方」だけでも1ページ足す価値がある
- [ ] 動的SQL＋SQLインジェクション対策も詳細版のみ。アプリからSQLを組む現場では効く

### B-6. 文字列→日付・数値の変換失敗とクレンジング

- [ ] `MyWork/01_業務概要.md` §8 に「CSV取り込みは TEXTステージング → `TO_DATE` 型変換 → `TRIM`/`NULLIF` クレンジングの2段構え（移行実務のミニチュア）」と**方針として書き**、電子カルテDWHのDDLでは実践しているのに、**講義側に受け皿が無い**
- [ ] `TO_DATE` の書式ずれ・全角空白・`NULLIF(列,'')` は、データ移行タスクで最初に踏む

### B-7. `NULLS FIRST` / `NULLS LAST`

- [ ] ほぼ0件。`ORDER BY` で NULL がどこに来るか（PostgreSQLはASCで最後）は帳票の並び順で当たる。**1〜2行で済む**ので [[02_CRUDについて]] の ORDER BY の節に追記

## C. 優先度【低】／要判断

- [ ] **`pg_dump` / リストア** — [[99_補足_psqlコマンドチートシート]] に列挙のみ。「破壊的操作の前に退避」の作法としては A-1 の `CREATE TABLE AS SELECT` でも代替できる。ハンズオンにするかは時間次第
- [ ] **VACUUM / テーブル膨れ** — MVCCの代償として [[15-2_実践_ロックとMVCC]] に、運用面は `05_補足/講師用/講義の補足/17_運用とチューニング.md` にある。**講義本編に上げるか、補足に留めるか**の判断
- [ ] **パーティショニング・行レベルセキュリティ** — 保守で「既にそうなっている」に出会う可能性はあるが、研修範囲としては過剰。**入れない**判断でよさそう
- [ ] **再帰CTE（階層展開）** — [[99_補足_CTE（共通テーブル式）]] にあり。組織階層・部品表は実務にあるが、「発展問題ではCTE禁止」の方針（`MyWork/01_業務概要.md` §8）と衝突するので位置づけの判断が必要

## D. トピックの漏れではないが、あわせて点検したいこと

### D-1. 「追加課題」が 09・10 に無い（章間の非対称）

追加課題（罠ベースの実務直結演習）があるのは **01・02・03・04・06・07・08 のみ**。09以降は無い。

> **2026-08-19 の書式統一で、番号の呼び方が変わりました。** 「追加問題N」は廃止し、ファイル内の通し番号（`## 問題 N:`）に統一。必須と任意の境界は `## 追加課題（ここから先は任意）` の行で示します（→ [[問題・解答ページのフォーマット]] §4）。

- [ ] [[08_補足_結合]] が持つ実務3大罠のうち、演習があるのは **[[00_SQL研修/02_問題/08_結合]] 追加課題 問題3（1対多×1対多で行が増殖）だけ**。**「ON句とWHERE句の違い」と「LEFT JOIN を殺す INNER JOIN」には演習が無い**。JOINのバグ原因として最頻出の3つなので、ここの対称化は A項目より効く可能性がある
- [x] ~~[[00_SQL研修/02_問題/09_集合演算子]] は5問・追加問題なし（45行）。**`EXCEPT` による突合＝差分抽出**は障害調査の定番なので、実務寄りの追加問題を置く価値が高い~~ → **2026-08-19 対応**。問題1をUNIONの重複排除が見える題材に差し替え、`EXCEPT` の問題6を追加（全6問）。実務寄りの突合問題はまだ無い
- [ ] [[00_SQL研修/02_問題/10_サブクエリ]] も追加問題なし。[[改善案]] に「サブクエリあたりの問題を早めに取り組みたかった」という受講生の声が残っている

### D-2. 総合問題と「00〜10章厳守」ルールの整合

- [ ] [[00_SQL研修/02_問題/19_総合問題]] の問題3・問題6が**ウィンドウ関数前提**。`MyWork/01_業務概要.md` §8 の「SQL発展問題は講義00〜10章の範囲厳守（ウィンドウ関数・CTE禁止）」が総合問題を含むのか要確認。含むなら差し替え、含まない（iTunes・実務想定だけが対象）なら §8 に「総合問題は18章まで可」と明記して曖昧さを消す

### D-3. 章番号と講義資料の対応表が無い

- [ ] 11章（テーブル構造変更）と13章（プロシージャ）は問題・解答があるが、**独立した講義ノートが無い**（11 は [[01_RDBMSとDDL]] 末尾の「テーブル構造の変更と削除」、13 は [[12-5_関数とプロシージャ]] が実質の講義）。05・14・16 は欠番
- [ ] README に章番号→資料の対応表が無く、引き継ぎ時に「11章の資料はどこ？」で迷う。[[00_SQL研修/README]] に1表足すだけ

## E. 総括：まず手を付けるなら

| 順 | 何を | なぜ先か |
|---|---|---|
| 1 | **A-1 更新系SQL**（`INSERT...SELECT` / `UPDATE...FROM` / 一時テーブル / UPSERT） | 実務想定問題で既に書かせているのに講義が無い＝**現に穴が開いている**。実務タスク「一括更新」「データ移行」の中核 |
| 2 | **D-1 08・09・10 の追加問題** | 講義資料は既に良い（[[08_補足_結合]]）ので**作るのは演習だけ**。JOINのバグは現場で最頻出 |
| 3 | **A-3 アンチジョインと `NOT IN` の罠** | 障害調査に直結。既存の [[00_SQL研修/02_問題/09_集合演算子]]・[[00_SQL研修/02_問題/10_サブクエリ]] に接続するだけで足りる |
| 4 | **A-4 数値・丸め ＋ A-5 `date_trunc`** | 帳票・月次集計。演習側（追加問題）が既にあるので講義側を埋める形 |
| 5 | **B-3 Oracle/SQL Server 方言対応表** | 1ページで配属後の効果が大きい。新規の学習項目ではなく翻訳表なので安い |

> **A-7（SQLの自己検証の作法）は上の順位付けの外に置いてある。**構文の追加ではなく手順の明文化で、1ページで済み、A-1（退避）と15章（トランザクション）に接続するだけ。**「研修で徹底させます」と自分で書いた約束が未実装**という性格なので、A-1 と同時にやるのが自然。詳細は [[★SQLの現場で求められる人材想定★]] §3。
