
## 問5
集合論と述語論理を基に設計されているSQLでは、本来順番を扱う機能がありません。そのため、下記のように一工夫するか、集合的にランキングを考える必要があります。
ただ、後にやるwindow関数では順番を出す機能が直接的に提供されてます。これは、その辺りの原理主義よりも実用性が大事となってきて、近代に登場したものです。
### 解答（order by + limit）
```SQL
SELECT
	o.order_id,
	SUM(p.amount) AS sum_amount
FROM
	orders AS o
	INNER JOIN payments AS p ON o.order_id = p.order_id
GROUP BY
	o.order_id
HAVING
	SUM(amount) IN (
		SELECT DISTINCT
			SUM(amount) AS high_price
		FROM
			payments
		GROUP BY
			order_id
		ORDER BY
			SUM(amount) DESC
		LIMIT
			3
	)
ORDER BY
	sum_amount DESC,
	o.order_id;
```

### 解答（自己結合、再帰的集合）
再帰的に集合の要素数を増やし、その要素数でランキングを付ける方策です。
もちろんwith句を使えばより見やすくなります。
```SQL
-- 順位付を、自分より多い支払金額の集合の要素数という見方
SELECT
	p1.order_id,
	p1.total_amount,
	COUNT(DISTINCT p2.total_amount) AS ranking -- 同率を圧縮する
FROM
	(
		SELECT
			order_id,
			SUM(amount) AS total_amount
		FROM
			payments
		GROUP BY
			order_id
	) AS p1
	INNER JOIN (
		SELECT
			order_id,
			SUM(amount) AS total_amount
		FROM
			payments
		GROUP BY
			order_id
	) AS p2 ON p1.total_amount <= p2.total_amount -- 自分より低い支払金額のレコードの集合を作る
GROUP BY
	p1.order_id,
	p1.total_amount
HAVING
	COUNT(DISTINCT p2.total_amount) <= 3
ORDER BY
	ranking,
	p1.order_id
```
### 解答（相関スカラサブクエリ、再帰的集合）
もちろんwith句を使えばより見やすくなります。
```SQL
-- 順位付を、自分より多い支払金額の集合の要素数という見方
SELECT
	order_id,
	total_amount,
	ranking
FROM
	(
		SELECT
			order_id,
			total_amount,
			(
				SELECT
					COUNT(DISTINCT total_amount)
				FROM
					(
						SELECT
							order_id,
							SUM(amount) AS total_amount
						FROM
							payments
						GROUP BY
							order_id
					) AS p2
				WHERE
					p2.total_amount >= p1.total_amount
			) AS ranking
		FROM
			(
				SELECT
					order_id,
					SUM(amount) AS total_amount
				FROM
					payments
				GROUP BY
					order_id
			) AS p1
	)
WHERE
	ranking <= 3
ORDER BY
	ranking,
	order_id
```

## 問8
### 解法パターン整理

#### 1. 【王道】EXISTS + NOT EXISTS
**論理：** 「高い商品を買ったことがある」かつ「安い商品を買ったことがない」

```SQL
SELECT C.CUSTOMER_ID, C.NAME
FROM CUSTOMERS C
WHERE EXISTS (
    -- ① 平均より高い商品を買ったことがある
    SELECT 1
    FROM ORDERS O
    JOIN ORDERITEMS OI ON O.ORDER_ID = OI.ORDER_ID
    JOIN PRODUCTS P ON OI.PRODUCT_ID = P.PRODUCT_ID
    WHERE O.CUSTOMER_ID = C.CUSTOMER_ID
      AND P.PRICE > (SELECT AVG(PRICE) FROM PRODUCTS)
)
AND NOT EXISTS (
    -- ② 平均以下の商品を買ったことがない
    SELECT 1
    FROM ORDERS O
    JOIN ORDERITEMS OI ON O.ORDER_ID = OI.ORDER_ID
    JOIN PRODUCTS P ON OI.PRODUCT_ID = P.PRODUCT_ID
    WHERE O.CUSTOMER_ID = C.CUSTOMER_ID
      AND P.PRICE <= (SELECT AVG(PRICE) FROM PRODUCTS)
);
```
*   **相関サブクエリ度：** ★★★（二重に使っており、練習として最適）
*   **特徴：** 「高いのを買った」かつ「安いのを買ってない」＝「高いもの**だけ**買った」というロジックが明確。
*   **未購入者の扱い：** ①がFalseになるため、自然に除外されます。

#### 2. 【スマート】スカラサブクエリでの比較 (MIN利用)
**論理：** 「その人が買った最も安い商品の価格」が「全体の平均価格」より高い。

```SQL
SELECT C.CUSTOMER_ID, C.NAME
FROM CUSTOMERS C
WHERE (
    SELECT MIN(P.PRICE)
    FROM ORDERS O
    JOIN ORDERITEMS OI ON O.ORDER_ID = OI.ORDER_ID
    JOIN PRODUCTS P ON OI.PRODUCT_ID = P.PRODUCT_ID
    WHERE O.CUSTOMER_ID = C.CUSTOMER_ID
) > (SELECT AVG(PRICE) FROM PRODUCTS);
```
*   **相関サブクエリ度：** ★★★
*   **特徴：** 非常に簡潔です。
*   **未購入者の扱い：** 購入履歴がない場合、`MIN(PRICE)` は `NULL` になります。SQLにおいて `NULL > 数値` の判定は `UNKNOWN` (False扱い) となるため、**追加の条件なしで未購入者を自動的に除外できます。** これが最もバグの少ない書き方と言えます。


#### 3. 【集合演算】EXCEPT を使う (PostgreSQL推奨)
**論理：** 「平均より高い商品を買った顧客IDの集合」引く「平均以下の商品を買った顧客IDの集合」。

```SQL
SELECT C.CUSTOMER_ID, C.NAME
FROM CUSTOMERS C
WHERE C.CUSTOMER_ID IN (
    -- 平均より高い商品を買った人
    SELECT O.CUSTOMER_ID
    FROM ORDERS O
    JOIN ORDERITEMS OI ON O.ORDER_ID = OI.ORDER_ID
    JOIN PRODUCTS P ON OI.PRODUCT_ID = P.PRODUCT_ID
    WHERE P.PRICE > (SELECT AVG(PRICE) FROM PRODUCTS)
    
    EXCEPT
    
    -- 平均以下の商品を買った人
    SELECT O.CUSTOMER_ID
    FROM ORDERS O
    JOIN ORDERITEMS OI ON O.ORDER_ID = OI.ORDER_ID
    JOIN PRODUCTS P ON OI.PRODUCT_ID = P.PRODUCT_ID
    WHERE P.PRICE <= (SELECT AVG(PRICE) FROM PRODUCTS)
);
```
*   **相関サブクエリ度：** ★☆☆ (非相関サブクエリ + 集合演算)
*   **特徴：** SQLらしい集合思考の解法です。PostgreSQLなど `EXCEPT` (OracleならMINUS) が使える環境では非常に可読性が高いです。
*   **未購入者の扱い：** 最初の集合（高い商品を買った人）に含まれないため、自動的に除外されます。

#### 4. 【非推奨】IN + NOT IN
**論理：** 「何か買ったことがある」かつ「安い商品を買った人リストに含まれない」。

```SQL
SELECT C.CUSTOMER_ID, C.NAME
FROM CUSTOMERS C
WHERE C.CUSTOMER_ID IN (
    -- 何か買ったことがある
    SELECT O.CUSTOMER_ID FROM ORDERS O
)
AND C.CUSTOMER_ID NOT IN (
    -- 安い商品を買った人リスト
    SELECT O.CUSTOMER_ID
    FROM ORDERS O
    JOIN ORDERITEMS OI ON O.ORDER_ID = OI.ORDER_ID
    JOIN PRODUCTS P ON OI.PRODUCT_ID = P.PRODUCT_ID
    WHERE P.PRICE <= (SELECT AVG(PRICE) FROM PRODUCTS)
    -- ※本来はここで WHERE O.CUSTOMER_ID IS NOT NULL が必要だがPKなので省略可
);
```
*   **相関サブクエリ度：** ★☆☆ (非相関サブクエリ)
*   **特徴：** 直感的ですが、`NOT IN` はNULLが含まれると全滅するリスクがあるため、実務では敬遠されがちです（今回はPKなので安全だが、注意が必要）。

#### 5. 【参考】HAVING (集約)
**論理：** グルーピングして最小値を比較。

```SQL
SELECT C.CUSTOMER_ID, C.NAME
FROM CUSTOMERS C
JOIN ORDERS O ON C.CUSTOMER_ID = O.CUSTOMER_ID
JOIN ORDERITEMS OI ON O.ORDER_ID = OI.ORDER_ID
JOIN PRODUCTS P ON OI.PRODUCT_ID = P.PRODUCT_ID
GROUP BY C.CUSTOMER_ID, C.NAME
HAVING MIN(P.PRICE) > (SELECT AVG(PRICE) FROM PRODUCTS);
```
*   **相関サブクエリ度：** ☆☆☆ (HAVING句内の非相関サブクエリ)
*   **特徴：** 「結合と集約」の問題としては正解ですが、「相関サブクエリ」の出題意図からは外れます。

#### 6.【参考】(HAVING COUNT 条件付き集約)
##### パターンA：減点方式（NGな商品が0個）

```SQL
-- countのパターン
SELECT
    c.customer_id,
    c.name
FROM
    customers c
    JOIN orders o ON c.customer_id = o.customer_id
    JOIN orderitems oi ON o.order_id = oi.order_id
    JOIN products p ON oi.product_id = p.product_id
GROUP BY
    c.customer_id,
    c.name
HAVING
    -- 平均価格以下の商品数が0個であること
    COUNT(CASE WHEN p.price <= (SELECT AVG(price) FROM products) THEN 1 END) = 0;
```
##### パターンB：加点方式（全数 ＝ OKな商品数）

```SQL
-- countのパターン
SELECT
	c.customer_id,
	c.name
FROM
	customers c
	JOIN orders o ON c.customer_id = o.customer_id
	JOIN orderitems oi ON o.order_id = oi.order_id
	JOIN products p ON oi.product_id = p.product_id
GROUP BY
	c.customer_id,
	c.name
HAVING
	-- 顧客ごとに全ての明細と値段が平均以上の明細が同数の顧客のみ絞る
	COUNT(*) = COUNT(CASE WHEN p.price > (SELECT AVG(price) FROM products) THEN 1 END)
```
