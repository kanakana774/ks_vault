# PL/pgSQL 実践講座：第3章 SQLの実行と結果の取得

## 3.1 SELECT INTO による変数への代入

PL/pgSQL内でクエリ結果を変数に格納する最も基本的な方法が `SELECT ... INTO` です。

### 重要な挙動と `STRICT` オプション
通常の `SELECT INTO` は、結果が 0 行でもエラーにならず、変数に `NULL` が代入されます。しかし、**「必ず 1 行あるはず」**というロジックで `NULL` が入ると、後続の処理でバグを引き起こします。これを防ぐのが `STRICT` オプションです。

### 実演：STRICT を用いた安全なデータ取得
```sql
DO $$
DECLARE
    v_name employees.name%TYPE;
    v_salary employees.salary%TYPE;
BEGIN
    -- 1. 通常の SELECT INTO (0行でもエラーにならない)
    SELECT name INTO v_name FROM employees WHERE emp_id = 999;
    RAISE NOTICE '1. Non-Strict: name is %', v_name; -- NULL と表示される

    -- 2. STRICT を指定 (0行だと例外を投げる)
    BEGIN
        SELECT name, salary INTO STRICT v_name, v_salary 
        FROM employees WHERE emp_id = 999;
    EXCEPTION
        WHEN NO_DATA_FOUND THEN
            RAISE NOTICE '2. Strict: データが見つかりませんでした (期待通りの挙動)';
        WHEN TOO_MANY_ROWS THEN
            RAISE NOTICE '2. Strict: 複数行返ってきました';
    END;

    -- 3. 複数列を一度に代入することも可能
    SELECT name, salary INTO STRICT v_name, v_salary 
    FROM employees WHERE emp_id = 1;
    RAISE NOTICE '3. Result: % earns %', v_name, v_salary;
END;
$$ LANGUAGE plpgsql;
```

## 3.2 DMLの結果取得：`RETURNING ... INTO`

`INSERT`, `UPDATE`, `DELETE` を行った際、その変更された値を再度 `SELECT` し直すのは非効率です。`RETURNING` 句を使うことで、更新された値を直接変数にキャッチできます。

### 実演：自動採番 ID や更新後の値を即座に取得
```sql
DO $$
DECLARE
    v_new_id integer;
    v_old_salary numeric;
    v_new_salary numeric;
BEGIN
    -- 1. INSERT した ID を取得
    INSERT INTO employees (name, dept_id, salary)
    VALUES ('New Engineer', 2, 800000)
    RETURNING emp_id INTO v_new_id;
    
    RAISE NOTICE 'Inserted ID: %', v_new_id;

    -- 2. UPDATE 前後の値を同時に取得 (現場でよく使うログ用パターン)
    -- ここでは salary を 10% アップさせ、新旧の値を記録
    UPDATE employees
    SET salary = salary * 1.1
    WHERE emp_id = v_new_id
    RETURNING salary INTO v_new_salary;
    
    RAISE NOTICE 'Update Complete: New Salary = %', v_new_salary;
END;
$$ LANGUAGE plpgsql;
```

## 3.3 結果の破棄と存在チェック：`PERFORM` と `FOUND`

「データの中身は要らないが、条件に合う行が存在するかだけ知りたい」場合や「副作用（関数の実行）だけが目的」の場合、`SELECT` を使うと「結果の行き先がない」というエラーになります。ここで `PERFORM` を使用します。

### 特殊変数 `FOUND`
直前の `SELECT INTO` や `PERFORM`、`UPDATE` 等が **1 行以上影響を与えたかどうか** を保持する論理値です。

### 実演：存在チェックとFOUNDの活用
```sql
DO $$
DECLARE
    v_target_id integer := 1;
BEGIN
    -- 1. 存在確認 (値は不要なので PERFORM)
    PERFORM 1 FROM employees WHERE emp_id = v_target_id;
    
    IF FOUND THEN
        RAISE NOTICE 'ID % は存在します。', v_target_id;
    ELSE
        RAISE NOTICE 'ID % は存在しません。', v_target_id;
    END IF;

    -- 2. UPDATE されたかどうかの判定
    UPDATE employees SET salary = salary + 1 WHERE emp_id = 999;
    
    IF NOT FOUND THEN
        RAISE NOTICE '更新対象の行がありませんでした。';
    END IF;
END;
$$ LANGUAGE plpgsql;
```

## 3.4 実行情報の詳細取得：`GET DIAGNOSTICS`

`FOUND` よりも詳細な情報（例：具体的に何行更新されたか）が必要な場合は `GET DIAGNOSTICS` コマンドを使用します。

### 実演：更新件数 (ROW_COUNT) の取得
```sql
DO $$
DECLARE
    v_count integer;
BEGIN
    -- Engineering部署(dept_id=2)の全員を昇給
    UPDATE employees 
    SET salary = salary + 50000 
    WHERE dept_id = 2;

    -- 直前の SQL の影響行数を取得
    GET DIAGNOSTICS v_count = ROW_COUNT;

    RAISE NOTICE 'Engineering部署の % 名を更新しました。', v_count;
END;
$$ LANGUAGE plpgsql;
```

## 3.5 実践：UPSERT パターン (INSERT ... ON CONFLICT)

現場で非常に多い「データがあれば更新、なければ挿入」という処理を、PL/pgSQL内で完結させる最も効率的な方法です。

### 実演：PL/pgSQL内での UPSERT と結果判定
```sql
DO $$
DECLARE
    r_emp employees%ROWTYPE;
BEGIN
    -- INSERT を試み、衝突(emp_id=1)したら UPDATE する
    -- RETURNING を使うことで、INSERT/UPDATE いずれの場合も最新の状態を取得できる
    INSERT INTO employees (emp_id, name, dept_id, salary)
    VALUES (1, 'Taro Tanaka (Updated)', 1, 550000)
    ON CONFLICT (emp_id) DO UPDATE 
    SET name = EXCLUDED.name,
        salary = EXCLUDED.salary
    RETURNING * INTO r_emp;

    RAISE NOTICE 'Final State: ID=%, Name=%, Salary=%', r_emp.emp_id, r_emp.name, r_emp.salary;
END;
$$ LANGUAGE plpgsql;
```

## 3.6 まとめ

1.  **「1行あるはず」のクエリには `STRICT` を付けよ**: `NULL` によるサイレントなバグを防ぐ最強の防御策です。
2.  **`SELECT` を 2 回投げるな**: `UPDATE ... RETURNING` を使えば、更新と確認を 1 回のクエリで完結でき、パフォーマンスと一貫性が向上します。
3.  **存在チェックは `PERFORM` + `FOUND` で**: 変数への代入コストすら惜しむのが良い書き方です。
4.  **`ROW_COUNT` は業務ロジックの要**: 「1行だけ更新されるはずが0行だった（または複数行だった）」という状態を `GET DIAGNOSTICS` で検知し、エラーを投げる癖をつけましょう。
