# PL/pgSQL 実践講座：第2章 変数とデータ型


## 2.1 変数の宣言と初期化のテクニック

PL/pgSQLでは、変数は必ず `DECLARE` セクションで宣言する必要があります。

### 基本構文と演算子
値の代入には `:=` を使用します（SQLの `=` との混同を避けるため、手続き型言語としては `:=` が推奨されますが、PostgreSQL 9.4以降は `=` も許容されています）。

### 実演：堅牢な変数宣言 (`CONSTANT`, `NOT NULL`)
現場では、安易な `NULL` の混入を防ぐための `NOT NULL` 制約や、不意の書き換えを防ぐ `CONSTANT` の活用が推奨されます。

```sql
DO $$
DECLARE
    -- 宣言と同時に初期化
    v_tax_rate    CONSTANT numeric := 0.10; -- 定数：以降書き換え不可
    v_msg         text DEFAULT 'Processing...'; -- DEFAULTキーワードも使用可能
    v_required_id integer NOT NULL := 100; -- NOT NULL制約：NULLを代入しようとするとエラー
    
    v_calculated_salary numeric;
BEGIN
    v_calculated_salary := 500000 * (1 + v_tax_rate);
    
    RAISE NOTICE 'Message: %', v_msg;
    RAISE NOTICE 'Calculated: %', v_calculated_salary;
    
    -- v_tax_rate := 0.15; -- コメントを外して実行すると ERROR: variable "v_tax_rate" is declared CONSTANT
    -- v_required_id := NULL; -- コメントを外して実行すると ERROR: variable "v_required_id" is declared NOT NULL
END;
$$ LANGUAGE plpgsql;
```

## 2.2 特殊な型属性：`%TYPE` と `%ROWTYPE`

現場でバリバリ書くエンジニアが最も多用すべき機能です。これを使うことで、**データベースのテーブル定義（列のデータ型や長さ）が変更されても、PL/pgSQL側のコードを修正する必要がなくなります。**

### `%TYPE` (列の型を継承)
特定のテーブルの特定の列と同じ型を定義します。

### `%ROWTYPE` (行全体の型を継承)
テーブルやビューの1行全体を保持する構造体を定義します。

### 実演：スキーマ連動型の変数
```sql
DO $$
DECLARE
    -- employeesテーブルのname列と同じ型
    v_emp_name employees.name%TYPE;
    
    -- employeesテーブルの1行分を丸ごと格納
    r_emp employees%ROWTYPE;
BEGIN
    -- 1. %TYPEへの代入
    SELECT name INTO v_emp_name FROM employees WHERE emp_id = 1;
    RAISE NOTICE 'Name via %%TYPE: %', v_emp_name;

    -- 2. %ROWTYPEへの代入 (行全体をSELECT * INTOで受け取る)
    SELECT * INTO r_emp FROM employees WHERE emp_id = 2;
    
    -- ドット演算子で各列にアクセス可能
    RAISE NOTICE 'ID: %, Name: %, Salary: %', r_emp.emp_id, r_emp.name, r_emp.salary;
    
    -- 個別のフィールドを書き換えることも可能
    r_emp.salary := r_emp.salary * 1.1;
    RAISE NOTICE 'Updated Salary in Memory: %', r_emp.salary;
END;
$$ LANGUAGE plpgsql;
```

## 2.3 複合データ型：`RECORD` と `CREATE TYPE`

### `RECORD` 型
`%ROWTYPE` と似ていますが、**「構造が実行時まで決まらない」**という柔軟性を持ちます。特定のテーブルに紐付かないクエリの結果（JOINした結果など）を受け取るのに最適です。

### 実演：RECORD型による柔軟なデータ取得
```sql
DO $$
DECLARE
    -- 構造を指定せずに宣言
    rec RECORD;
BEGIN
    -- JOINした結果を受け取る（%ROWTYPEでは定義できない構造）
    FOR rec IN (
        SELECT e.name, d.dept_name 
        FROM employees e 
        JOIN departments d ON e.dept_id = d.dept_id
    ) LOOP
        RAISE NOTICE 'Employee: %, Dept: %', rec.name, rec.dept_name;
    END LOOP;
END;
$$ LANGUAGE plpgsql;
```

### ユーザー定義型 (`CREATE TYPE`)
複数の関数やプロシージャで共通して使いたい構造は、DBオブジェクトとして型を作成しておくと便利です。

```sql
-- 事前に定義（1回のみ実行）
CREATE TYPE employee_summary AS (
    full_name text,
    is_high_paid boolean
);

DO $$
DECLARE
    v_summary employee_summary;
BEGIN
    -- 値のセット (ROWコンストラクタ)
    v_summary := ROW('Ichiro Sato', true);
    
    RAISE NOTICE 'Summary: Name=% HighPaid=%', v_summary.full_name, v_summary.is_high_paid;
END;
$$ LANGUAGE plpgsql;
```

## 2.4 コレクション：配列 (`ARRAY`)

大量のIDリストを一度に処理したり、関数の引数として複数の値を渡したりする際に必須の知識です。

### 実演：配列の操作と集約
```sql
DO $$
DECLARE
    -- 初期値付き配列
    v_ids integer[] := ARRAY[1, 2, 3];
    v_names text[];
    v_id integer;
BEGIN
    -- 1. 配列への追加
    v_ids := v_ids || 4; -- 配列の結合

    -- 2. クエリの結果を配列に集約 (array_agg)
    SELECT array_agg(name) INTO v_names FROM employees;
    RAISE NOTICE 'All Names: %', v_names;
    RAISE NOTICE 'Second Name: %', v_names[2]; -- PostgreSQLの配列は1から始まる

    -- 3. 配列をループで回す (FOREACH)
    FOREACH v_id IN ARRAY v_ids LOOP
        RAISE NOTICE 'Processing ID: %', v_id;
    END LOOP;
END;
$$ LANGUAGE plpgsql;
```

## 2.5 JSON と JSONB の活用

現代のエンジニアにとって、PL/pgSQL内でのJSON操作は避けて通れません。特に性能面で有利な `JSONB` を中心に解説します。

### 実演：JSONBデータの構築と抽出
```sql
DO $$
DECLARE
    v_data jsonb;
    v_emp_count integer;
    v_avg_salary numeric;
BEGIN
    -- 1. 集計データを動的にJSONとして構築
    SELECT count(*), avg(salary) INTO v_emp_count, v_avg_salary FROM employees;
    
    v_data := jsonb_build_object(
        'timestamp', now(),
        'summary', jsonb_build_object(
            'count', v_emp_count,
            'average_salary', v_avg_salary
        ),
        'target_ids', (SELECT jsonb_agg(emp_id) FROM employees)
    );

    RAISE NOTICE 'JSON Result: %', jsonb_pretty(v_data);

    -- 2. JSONから特定の値を抽出 (演算子 ->, ->>)
    -- ->> はテキストとして取得、-> はJSONBオブジェクトとして取得
    RAISE NOTICE 'Extract Count: %', v_data -> 'summary' ->> 'count';
    
    -- 3. キーの存在チェック
    IF v_data ? 'summary' THEN
        RAISE NOTICE 'Key "summary" exists.';
    END IF;
END;
$$ LANGUAGE plpgsql;
```

## 2.6 まとめとエンジニア向けのベストプラクティス

1.  **%TYPE / %ROWTYPE を徹底活用せよ**: テーブル定義の変更に強い、メンテナンス性の高いコードになります。
2.  **RECORD は「使い捨て」または「動的クエリ」に**: 型が決まっているなら %ROWTYPE の方が安全（コンパイル時に列名の存在チェックが走るため）です。
3.  **JSONB は複雑な戻り値に**: 複数の戻り値がある場合、`OUT` パラメータを増やすよりも `JSONB` で一つのオブジェクトとして返した方が、将来の拡張性が高い場合があります。
4.  **NULLを恐れよ**: `NOT NULL` 制約を活用し、変数の初期化を忘れないことで、実行時のバグを大幅に減らせます。
