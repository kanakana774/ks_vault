# PL/pgSQL 実践講座：第5章 関数とプロシージャ

これまでの章では、`DO` ブロックを用いてその場で実行するコードを学びました。第5章では、ロジックをデータベース内に永続化し、再利用可能にするための **「関数 (FUNCTION)」** と **「プロシージャ (PROCEDURE)」** について詳解します。

現場のエンジニアにとって、この両者の使い分けと、パフォーマンスに直結する「変動性（Volatility）」、およびセキュリティ設定を理解することは、堅牢なシステム設計の要となります。

## 5.1 関数 (FUNCTION) と プロシージャ (PROCEDURE) の違い

PostgreSQL 11 でプロシージャが導入されて以降、明確な使い分けが必要になりました。

| 項目 | 関数 (FUNCTION) | プロシージャ (PROCEDURE) |
| :--- | :--- | :--- |
| **主な目的** | 計算、データ取得、変換 | 一連の業務処理の実行 |
| **戻り値** | **必須** (`RETURNS` 句) | **なし** (戻り値という概念がない) |
| **呼び出し方** | `SELECT`, `WHERE` 句などの一部として | `CALL` コマンドで単独実行 |
| **トランザクション** | **不可** (内部で `COMMIT/ROLLBACK` できない) | **可能** (自律的にトランザクションを制御) |

## 5.2 関数 (CREATE FUNCTION) の詳細

### 5.2.1 基本的なスカラー関数
一つの値を返す最も標準的な形式です。

**実演：給与から源泉徴収額を計算する関数**
```sql
CREATE OR REPLACE FUNCTION calculate_withholding_tax(p_salary numeric)
RETURNS numeric AS $$
BEGIN
    -- 簡易的な税計算ロジック
    IF p_salary > 600000 THEN
        RETURN round(p_salary * 0.20);
    ELSE
        RETURN round(p_salary * 0.10);
    END IF;
END;
$$ LANGUAGE plpgsql;

-- 呼び出し
SELECT name, salary, calculate_withholding_tax(salary) as tax FROM employees;
```

### 5.2.2 テーブルを返す関数 (RETURNS TABLE)
現場で「複雑な集計ロジックをビューのように扱いたい」場合に非常に強力です。

**実演：部署ごとの統計情報を返す関数**
```sql
CREATE OR REPLACE FUNCTION get_dept_stats()
RETURNS TABLE(d_name text, avg_sal numeric, emp_count bigint) AS $$
BEGIN
    RETURN QUERY
    SELECT 
        d.dept_name,
        round(avg(e.salary), 2),
        count(e.emp_id)
    FROM departments d
    LEFT JOIN employees e ON d.dept_id = e.dept_id
    GROUP BY d.dept_name;
END;
$$ LANGUAGE plpgsql;

-- 呼び出し (テーブルのように扱う)
SELECT * FROM get_dept_stats() WHERE emp_count > 0;
```

## 5.3 プロシージャ (CREATE PROCEDURE) とトランザクション制御

プロシージャの最大の特徴は、**「処理の途中でコミットできること」**です。大量データのバッチ処理において、メモリ不足やログの肥大化を防ぐために必須の機能です。

**実演：分割コミットを行うバッチ更新プロシージャ**
```sql
CREATE OR REPLACE PROCEDURE batch_update_salaries(p_increment numeric) AS $$
DECLARE
    r RECORD;
BEGIN
    FOR r IN SELECT emp_id, name FROM employees LOOP
        UPDATE employees SET salary = salary + p_increment WHERE emp_id = r.emp_id;
        RAISE NOTICE '% の給与を更新しました', r.name;
        
        -- ここで一回ごとに確定（実際は1000件ごとなどで判定するのが一般的）
        COMMIT; 
    END LOOP;
END;
$$ LANGUAGE plpgsql;

-- 呼び出し
CALL batch_update_salaries(100.00);
```

## 5.4 引数の高度な機能

### 5.4.1 引数モード (IN, OUT, INOUT)
*   `IN` (デフォルト): 入力用。
*   `OUT`: 戻り値として使用。プロシージャで複数の値を「返したように見せる」際にも使われます。
*   `INOUT`: 入力として受け取り、加工して同じ変数で返します。

**実演：OUT引数を用いたプロシージャ**
```sql
CREATE OR REPLACE PROCEDURE get_employee_summary(
    p_id IN integer,
    p_name OUT text,
    p_sal OUT numeric
) AS $$
BEGIN
    SELECT name, salary INTO p_name, p_sal FROM employees WHERE emp_id = p_id;
END;
$$ LANGUAGE plpgsql;

-- 呼び出し（匿名ブロックで受け取る例）
DO $$
DECLARE
    v_name text;
    v_sal numeric;
BEGIN
    CALL get_employee_summary(1, v_name, v_sal);
    RAISE NOTICE 'Name: %, Salary: %', v_name, v_sal;
END;
$$;
```

### 5.4.2 可変長引数 (VARIADIC)
任意の数の引数を配列として受け取ります。

```sql
CREATE OR REPLACE FUNCTION multi_sum(VARIADIC p_nums numeric[])
RETURNS numeric AS $$
DECLARE
    v_total numeric := 0;
    v_n numeric;
BEGIN
    FOREACH v_n IN ARRAY p_nums LOOP
        v_total := v_total + v_n;
    END LOOP;
    RETURN v_total;
END;
$$ LANGUAGE plpgsql;

SELECT multi_sum(10, 20, 30, 0.5); -- 60.5
```

## 5.5 関数の変動性 (Volatility Category)

現場で意外と見落とされるのがこの設定です。オプティマイザはこの情報を見て実行計画を最適化します。

1.  **VOLATILE** (デフォルト): 呼び出されるたびに結果が変わる可能性がある（DB更新を含むなど）。最適化されない。
2.  **STABLE**: 一つのクエリ実行内であれば、同じ引数に対して同じ結果を返すことが保証される。インデックススキャンなどで利用可能。
3.  **IMMUTABLE**: DBの状態に依存せず、常に同じ引数に対して同じ結果を返す（例：数値計算、文字列操作）。**関数ベースのインデックス**を作成するにはこれが必要。

```sql
-- 数値変換などの純粋なロジックは IMMUTABLE に設定して効率化する
CREATE OR REPLACE FUNCTION to_yen(p_dollar numeric)
RETURNS numeric AS $$
BEGIN
    RETURN round(p_dollar * 150); -- 固定レートの例
END;
$$ LANGUAGE plpgsql IMMUTABLE;
```

## 5.6 セキュリティ設定 (SECURITY INVOKER / DEFINER)

*   **SECURITY INVOKER** (デフォルト): 関数を **「実行した人」** の権限で動作。
*   **SECURITY DEFINER**: 関数を **「作成した人」** の権限で動作。

### 現場での注意：SECURITY DEFINER の「search_path」脆弱性
`SECURITY DEFINER` を使う場合、悪意のあるユーザーが同名の偽テーブルを別スキーマに作って実行させる「検索パス攻撃」が可能です。これを防ぐため、必ず `SET search_path` を明示します。

```sql
CREATE OR REPLACE FUNCTION privileged_delete(p_id integer)
RETURNS void AS $$
BEGIN
    DELETE FROM employees WHERE emp_id = p_id;
END;
$$ LANGUAGE plpgsql 
   SECURITY DEFINER 
   SET search_path = public, pg_temp; -- 安全な検索パスを固定
```

## 5.7 まとめとエンジニア向けのベストプラクティス

1.  **「SELECTで使いたい」なら FUNCTION、「バッチ更新したい」なら PROCEDURE**: トランザクション制御が必要かどうかが最大の判断基準です。
2.  **`CREATE OR REPLACE` の罠に注意**: 引数の型や数、戻り値の型を変更する場合、`OR REPLACE` は失敗します。その場合は `DROP FUNCTION/PROCEDURE` が必要です。
3.  **名前付き引数で可読性を上げよ**:
    ```sql
    -- 呼び出し時に名前を指定（順序を気にしなくて良い）
    SELECT calculate_withholding_tax(p_salary => 800000);
    ```
4.  **変動性 (Volatility) を意識せよ**: 不要に `VOLATILE` な関数を `WHERE` 句で使うと、全行スキャン時にパフォーマンスが劇的に低下します。可能なら `STABLE` や `IMMUTABLE` にできないか検討してください。
