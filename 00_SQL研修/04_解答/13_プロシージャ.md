### 前準備：ID採番の補助
本来は `SEQUENCE` を使うべきですが、今回は「手動採番」の練習も含めるため、各プロシージャ内で `MAX(id) + 1` を計算する手法を採用します。
※実務では同時実行時の重複エラーを防ぐため `SEQUENCE` や `UUID` を使いますが、学習用として「テーブルの現在の状態を確認して次を決める」ロジックを組み込みます。

### 問題 1：会員ランク更新プロシージャ
**【要件】**
引数に `customer_id` と `membership_id` を受け取り、指定された顧客の会員ランクを更新するストアドプロシージャ `UPDATE_CUSTOMER_MEMBERSHIP` を作成してください。

*   **バリデーション**: 
	* 指定された `membership_id` が `Memberships` テーブルに存在しない場合は、「指定された会員ランクが存在しません。」というメッセージで例外を発生させてください。
	* 指定された `customer_id` が `Customers` テーブルに存在しない場合は、「顧客IDが存在しません。」というメッセージで例外を発生させてください。
*   **通知**: 更新に成功した場合、「顧客 [名前]（ID:[ID]）のランクを [ランク名] に更新しました。」という通知（NOTICE）を出してください。

```SQL
CREATE OR REPLACE PROCEDURE UPDATE_CUSTOMER_MEMBERSHIP (
    p_customer_id INT,
    p_new_membership_id INT
) LANGUAGE plpgsql AS $$
DECLARE
    v_customer_name VARCHAR(100);
    v_rank_name VARCHAR(50);
BEGIN
    -- 会員ランクの存在確認
    SELECT rank_name INTO v_rank_name FROM Memberships WHERE membership_id = p_new_membership_id;
    IF NOT FOUND THEN
        RAISE EXCEPTION '指定された会員ランク（ID:%）が存在しません。', p_new_membership_id;
    END IF;

    -- 顧客の存在確認と名前取得
    SELECT name INTO v_customer_name FROM Customers WHERE customer_id = p_customer_id;
    IF NOT FOUND THEN
        RAISE EXCEPTION '顧客ID:% が見つかりません。', p_customer_id;
    END IF;

    -- 更新
    UPDATE Customers SET membership_id = p_new_membership_id WHERE customer_id = p_customer_id;

    RAISE NOTICE '顧客 %（ID:%）のランクを % に更新しました。', v_customer_name, p_customer_id, v_rank_name;
END;
$$;
```

### 問題 2：購入履歴確認付きレビュー投稿プロシージャ
**【要件】**
レビューの整合性を守るため、商品を購入したことがある顧客のみが投稿できるプロシージャ `POST_PRODUCT_REVIEW` を作成してください。

*   **引数**: `p_customer_id`, `p_product_id`, `p_rating`, `p_comment`
*   **ID採番**: `review_id` は `Reviews` テーブルの最大値 + 1 を自動で割り当ててください（初期データがない場合は1とする）。
*   **バリデーション**: 
    1. 顧客がその商品を1度も注文（Orders & OrderItems）していない場合、「購入履歴がないためレビューできません。」という例外を発生させます。
    2. すでにその顧客がその商品にレビューを書いている場合（一意制約違反の防止）、「既にレビュー投稿済みです。」という例外を発生させます。
*   **登録**: 成功時、`review_date` には現在日付を入れて登録してください。

```SQL
CREATE OR REPLACE PROCEDURE POST_PRODUCT_REVIEW (
    p_customer_id INT,
    p_product_id INT,
    p_rating INT,
    p_comment TEXT
) LANGUAGE plpgsql AS $$
DECLARE
    v_new_review_id INT;
    v_purchased BOOLEAN;
BEGIN
    -- 購入履歴の確認 (EXISTSを使用すると効率的)
    SELECT EXISTS (
        SELECT 1 FROM Orders o
        JOIN OrderItems oi ON o.order_id = oi.order_id
        WHERE o.customer_id = p_customer_id AND oi.product_id = p_product_id
    ) INTO v_purchased;

    IF NOT v_purchased THEN
        RAISE EXCEPTION '購入履歴がないためレビューできません。（Customer:%, Product:%）', p_customer_id, p_product_id;
    END IF;

    -- 投稿済みチェック
    IF EXISTS (SELECT 1 FROM Reviews WHERE customer_id = p_customer_id AND product_id = p_product_id) THEN
        RAISE EXCEPTION '既にレビュー投稿済みです。';
    END IF;

    -- IDの採番
    SELECT COALESCE(MAX(review_id), 0) + 1 INTO v_new_review_id FROM Reviews;

    -- 登録
    INSERT INTO Reviews (review_id, product_id, customer_id, rating, comment, review_date)
    VALUES (v_new_review_id, p_product_id, p_customer_id, p_rating, p_comment, CURRENT_DATE);

    RAISE NOTICE 'レビューを投稿しました（Review ID: %）', v_new_review_id;
END;
$$;
```

### 問題 3：複数倉庫対応の在庫引き当て注文プロシージャ
**【要件】**
1つの商品が複数の倉庫に分かれて保管されていることを考慮し、在庫が足りる倉庫から順番に引き当てて注文を作成するプロシージャ `PLACE_ORDER_WITH_STOCK_ALLOCATION` を作成してください。
>[!Note]
> 各倉庫から在庫チェックするのが難しければ、倉庫ID=1しか存在しないと仮定して問題解いてもらって大丈夫です！
> 余裕があれば各倉庫から在庫引き当てできるように拡張してみましょう！

*   **引数**: `p_customer_id`, `p_product_id`, `p_quantity`
*   **処理フロー**:
    1.  **在庫チェック**: `Inventory` テーブルから該当商品の合計在庫数を取得し、`p_quantity` 未満であれば「全倉庫で在庫が不足しています（合計在庫: X）」という例外を発生させる。
    2.  **注文登録**: `Orders` テーブルに新規登録（`status`は'Pending'）。`order_id` は MAX+1。
    3.  **明細登録**: `OrderItems` テーブルに登録。`order_item_id` は MAX+1。
    4.  **在庫引き当て（最重要）**: 
        *   `warehouse_id` の昇順に在庫を確認し、注文数に達するまで各倉庫の `stock_quantity` を減算（UPDATE）していく。
        *   例：注文10個に対し、倉庫Aに4個、倉庫Bに20個ある場合、倉庫Aを0個に、倉庫Bを14個に更新する。
*   **通知**: 完了後、「注文完了：Order ID [ID], 合計 [個数] 個の在庫を引き当てました。」と表示してください。

```SQL
CREATE OR REPLACE PROCEDURE PLACE_ORDER_WITH_STOCK_ALLOCATION (
    p_customer_id INT,
    p_product_id INT,
    p_quantity INT
) LANGUAGE plpgsql AS $$
DECLARE
    v_total_stock INT;
    v_new_order_id INT;
    v_new_item_id INT;
    v_remaining_qty INT := p_quantity;
    rec_inv RECORD;
BEGIN
    -- 1. 合計在庫チェック
    SELECT SUM(stock_quantity) INTO v_total_stock FROM Inventory WHERE product_id = p_product_id;
    IF v_total_stock IS NULL OR v_total_stock < p_quantity THEN
        RAISE EXCEPTION '全倉庫で在庫が不足しています（合計在庫: %）', COALESCE(v_total_stock, 0);
    END IF;

    -- 2. Order登録 (ID採番含む)
    SELECT COALESCE(MAX(order_id), 0) + 1 INTO v_new_order_id FROM Orders;
    INSERT INTO Orders (order_id, customer_id, order_date, status)
    VALUES (v_new_order_id, p_customer_id, CURRENT_DATE, 'Pending');

    -- 3. OrderItems登録 (ID採番含む)
    SELECT COALESCE(MAX(order_item_id), 0) + 1 INTO v_new_item_id FROM OrderItems;
    INSERT INTO OrderItems (order_item_id, order_id, product_id, quantity)
    VALUES (v_new_item_id, v_new_order_id, p_product_id, p_quantity);

    -- 4. 在庫引き当てループ
    FOR rec_inv IN 
        SELECT warehouse_id, stock_quantity 
        FROM Inventory 
        WHERE product_id = p_product_id AND stock_quantity > 0
        ORDER BY warehouse_id
    LOOP
        IF v_remaining_qty <= 0 THEN EXIT; END IF;

        IF rec_inv.stock_quantity >= v_remaining_qty THEN
            -- この倉庫で足りる
            UPDATE Inventory SET stock_quantity = stock_quantity - v_remaining_qty 
            WHERE product_id = p_product_id AND warehouse_id = rec_inv.warehouse_id;
            v_remaining_qty := 0;
        ELSE
            -- この倉庫の分を全て使い、次の倉庫へ
            UPDATE Inventory SET stock_quantity = 0 
            WHERE product_id = p_product_id AND warehouse_id = rec_inv.warehouse_id;
            v_remaining_qty := v_remaining_qty - rec_inv.stock_quantity;
        END IF;
    END LOOP;

    RAISE NOTICE '注文完了：Order ID %, 合計 % 個の在庫を引き当てました。', v_new_order_id, p_quantity;
END;
$$;
```

### 動作確認用テストケース

```sql
-- 問題1テスト
CALL UPDATE_CUSTOMER_MEMBERSHIP(1, 3); -- 成功：Alice(ID1)をGold(ID3)へ
CALL UPDATE_CUSTOMER_MEMBERSHIP(1, 99); -- 失敗：存在しないランク

-- 問題2テスト
CALL POST_PRODUCT_REVIEW(1, 1, 5, '最高！'); -- 成功：AliceはLaptop(ID1)を購入済み
CALL POST_PRODUCT_REVIEW(3, 1, 1, 'だめ');   -- 失敗：CharlieはLaptop未購入

-- 問題3テスト
-- 商品1(Laptop)は 倉庫1に50個、倉庫2に10個。合計60個。
CALL PLACE_ORDER_WITH_STOCK_ALLOCATION(1, 1, 55); 
-- 結果確認：
-- 倉庫1の在庫が 0 になり、倉庫2の在庫が 5 になっていれば正解。
SELECT * FROM Inventory WHERE product_id = 1;
```
