**`01_講義資料/` の完成品と対になる読み物です。** 役割は2つあります。

1. **完成品の「長い版」** … 調べたこと・議論・他DBとの比較を、根拠付きで残す
2. **完成品に入らなかった内容の置き場** … 難しすぎる／時間が足りなくて講義に載せられないが、**読めば分かる形で残しておきたい**もの

**配布するときは、`00_SQL研修` をコピーしてこのフォルダを削ってください。**

## 約束（詳細は vault 直下の [[CLAUDE]]）

- **段階で主役が変わる。** ①起草＝詳細版 → ②蒸留（一度きり）→ **③運用＝完成品**。
  **蒸留は繰り返さない**（完成品の作り込みが上書きで消えるため）
- 運用中に詳細版へ戻るのは3ケース。**(a) 逃がす**（完成品に載せられない発展内容を新規追記）／
  **(b) 還流**（完成品に足した事実が詳細版に無い）／**(c) 訂正**（詳細版の誤り・陳腐化が判明）
- **同期義務があるのは事実・判断だけ。** 言い回し・節の順序・例の差し替えは完成品が正で、ここは追わない
  > **完成品にあって詳細版に無い「事実」は同期漏れ。** 逆は正常
- 書き足すときは**結論だけ貼らない**。読み物なので**根拠と経緯を付ける**
- **(a) で逃がした発展内容は、講師の作業メモと混ぜない**（将来ここから発展編だけ切り出せなくなる）
- ファイル名は完成品と同名にせず **`_詳細` を付ける**（Obsidian のリンク解決が曖昧になるため）
- **リンクは片方向。** 詳細版 → 完成品 は貼ってよい。**完成品 → 詳細版 は貼らない**（配布先でリンク切れになる）
- **削るのは「言い方」。「どこまで通じる話か」の切り分け（🐘 印）は削らない**
- 章ごとに `_蒸留メモ_何を削ったか.md` を置き、**削った基準と、以後どうズレたか**を記録する
