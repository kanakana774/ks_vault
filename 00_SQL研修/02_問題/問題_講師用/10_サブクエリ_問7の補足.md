### 回答パターン一覧

#### 1. 【推奨】CTE（共通テーブル式）を使うパターン
**特徴:** 最も可読性が高く、論理構成（まず集計→次に抽出）が明確です。実務で最も好まれます。

```sql
WITH OrderPaymentTotals AS (
    -- 手順1: まず「注文ごと」の支払総額を計算する
    SELECT
        o.customer_id,
        o.order_id,
        SUM(p.amount) AS total_paid
    FROM
        orders o
        JOIN payments p ON o.order_id = p.order_id
    GROUP BY
        o.customer_id,
        o.order_id
)
-- 手順2: 顧客ごとに、手順1の結果から最大値を抽出する
SELECT
    c.customer_id,
    c.name,
    MAX(opt.total_paid) AS max_order_total
FROM
    customers c
    JOIN OrderPaymentTotals opt ON c.customer_id = opt.customer_id
GROUP BY
    c.customer_id,
    c.name;
```

#### 2. 【基本】FROM句でのサブクエリ（派生テーブル）パターン
**特徴:** CTEが使えない古いDBや、標準的なSQLの教科書的な書き方です。やっていることはCTEと同じです。

```sql
SELECT
    c.customer_id,
    c.name,
    MAX(sub_order_totals.total_paid) AS max_order_total
FROM
    customers c
    JOIN (
        -- ここで注文ごとの集計テーブルを一時的に作る
        SELECT
            o.customer_id,
            SUM(p.amount) AS total_paid
        FROM
            orders o
            JOIN payments p ON o.order_id = p.order_id
        GROUP BY
            o.customer_id, -- 結合用にcustomer_idも残す
            o.order_id
    ) AS sub_order_totals 
    ON c.customer_id = sub_order_totals.customer_id
GROUP BY
    c.customer_id,
    c.name;
```

#### 3. 【発展】相関サブクエリを使うパターン（SELECT句）
**特徴:** 「各行ごとに計算する」イメージです。論理的には合っていますが、データ量が多いとパフォーマンスが悪化する可能性があります。SQLの構文力を試すには良い例です。

```sql
SELECT
    c.customer_id,
    c.name,
    (
        -- その顧客の「注文ごとの合計」の中で最大のものを取り出す
        SELECT
            MAX(per_order.total_paid)
        FROM (
            -- 特定の注文ごとの合計を計算
            SELECT
                SUM(p.amount) AS total_paid
            FROM
                orders o
                JOIN payments p ON o.order_id = p.order_id
            WHERE
                o.customer_id = c.customer_id -- 【相関】外側の顧客IDと紐付け
            GROUP BY
                o.order_id
        ) AS per_order
    ) AS max_payment
FROM
    customers c
-- 支払実績がない顧客を除外したければここで制御、今回は全顧客表示ならLEFT JOIN的な挙動になる
ORDER BY
    c.customer_id;
```

#### 4. 【別解】ウィンドウ関数を使うパターン
**特徴:** `GROUP BY` を使わずに `DISTINCT` と `MAX() OVER()` を使う、ややモダンな書き方です。「最大額の注文IDも一緒に出したい」といった要件変更に強いです。

```sql
WITH OrderPaymentTotals AS (
    SELECT
        o.customer_id,
        o.order_id,
        SUM(p.amount) AS total_paid
    FROM
        orders o
        JOIN payments p ON o.order_id = p.order_id
    GROUP BY
        o.customer_id, o.order_id
)
SELECT DISTINCT
    c.customer_id,
    c.name,
    -- 顧客パーティション内での最大値を算出
    MAX(opt.total_paid) OVER(PARTITION BY c.customer_id) AS max_order_total
FROM
    customers c
    JOIN OrderPaymentTotals opt ON c.customer_id = opt.customer_id;
```

**誤答例のSQL:**
```sql
-- 【間違い】分割払いの合計が考慮されない
SELECT
    C.CUSTOMER_ID,
    C.NAME,
    MAX(P.AMOUNT) AS MAX_PAYMENT -- これだと1回の決済額の最大値になってしまう
FROM
    CUSTOMERS C
    JOIN ORDERS O ON C.CUSTOMER_ID = O.CUSTOMER_ID
    JOIN PAYMENTS P ON O.ORDER_ID = P.ORDER_ID
GROUP BY
    C.CUSTOMER_ID, C.NAME;
```

### まとめ


1.  **模範解答 (CTE + JOIN)**: 実務的で一番きれい。
2.  **別解 1 (FROM句サブクエリ)**: 伝統的な書き方。
3.  **別解 2 (SELECT句で相関サブクエリ)**: スカラサブクエリの練習用。
4.  **【重要】誤答例**: `MAX(amount)` を直接叩いてしまうパターン（分割払いの罠にハマる）。
