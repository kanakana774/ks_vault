
### 各国で最も売上が高かったジャンルと、その国の総売上におけるそのジャンルの売上比率を取得してください。

**ヒント:** サブクエリとウィンドウ関数を組み合わせて、国ごとのジャンル売上と国ごとの総売上を計算し、比率を求めます。`RANK()` または `ROW_NUMBER()` を使用して、各国のトップジャンルを特定できます。

**回答:**

```sql
WITH CountryGenreSales AS (
  SELECT
    i.billing_country AS country,
    g.name AS genre_name,
    SUM(il.quantity * il.unit_price) AS genre_sales
  FROM invoice AS i
  JOIN invoice_line AS il
    ON i.invoice_id = il.invoice_id
  JOIN track AS t
    ON il.track_id = t.track_id
  JOIN genre AS g
    ON t.genre_id = g.genre_id
  GROUP BY
    i.billing_country,
    g.name
), CountryTotalSales AS (
  SELECT
    i.billing_country AS country,
    SUM(i.total) AS total_country_sales
  FROM invoice AS i
  GROUP BY
    i.billing_country
)
SELECT
  cgs.country,
  cgs.genre_name,
  cgs.genre_sales,
  (cgs.genre_sales / cts.total_country_sales) * 100 AS sales_percentage
FROM CountryGenreSales AS cgs
JOIN CountryTotalSales AS cts
  ON cgs.country = cts.country
WHERE
  (cgs.country, cgs.genre_sales) IN (
    SELECT
      country,
      MAX(genre_sales)
    FROM CountryGenreSales
    GROUP BY
      country
  )
ORDER BY
  cgs.country,
  sales_percentage DESC;

-- 別パターン (ROW_NUMBERを使用)
WITH CountryGenreSalesRanked AS (
  SELECT
    i.billing_country AS country,
    g.name AS genre_name,
    SUM(il.quantity * il.unit_price) AS genre_sales,
    SUM(SUM(il.quantity * il.unit_price)) OVER (PARTITION BY i.billing_country) AS total_country_sales,
    ROW_NUMBER() OVER (PARTITION BY i.billing_country ORDER BY SUM(il.quantity * il.unit_price) DESC) AS rn
  FROM invoice AS i
  JOIN invoice_line AS il
    ON i.invoice_id = il.invoice_id
  JOIN track AS t
    ON il.track_id = t.track_id
  JOIN genre AS g
    ON t.genre_id = g.genre_id
  GROUP BY
    i.billing_country,
    g.name
)
SELECT
  country,
  genre_name,
  genre_sales,
  (genre_sales / total_country_sales) * 100 AS sales_percentage
FROM CountryGenreSalesRanked
WHERE
  rn = 1
ORDER BY
  country,
  sales_percentage DESC;
```


複雑な集約SQLを扱う上で非常に重要かつ「全エンジニアが一度はハマる」典型的なポイントです。

### 1. 「1対多の結合」による数値の膨れ上がり（ファンアウト）

**【言語化】**
「1（invoice）」のテーブルにある値を、「多（invoice_line）」を結合した状態で `SUM` してはいけない。

**【解説】**
*   **何が起きたか:** `invoice`（1）に `invoice_line`（多）を結合すると、1つの `invoice_id` に対して複数行が生成されます。この状態で `invoice.total` を `SUM` すると、同じ金額が明細の数だけ重複して足されてしまい、合計値が本来の数倍になってしまいます。
*   **対策:** 
    *   売上を計算する際は、**「最も細かい粒度（この場合は `invoice_line`）」の数値（単価×数量）を使って集計する**のが鉄則です。
    *   もし親テーブル（invoice）の値をどうしても使いたい場合は、結合する前に集約を済ませるか、今回の回答のように `invoice_line` 側から値を積み上げます。

---

### 2. 集約の粒度（データポータル）の意識

**【言語化】**
「AごとのB」を求める際、データには2種類の粒度（Country+Genre と Countryのみ）が混在していることを認識する。

**【解説】**
*   **何が起きたか:** 最終的に出したいのは「国ごとのトップジャンル」ですが、計算過程では以下の2つのスコープが必要でした。
    1.  **「国×ジャンル」** の売上（分子）
    2.  **「国」** の総売上（分母）
*   **対策:** これを一度の `GROUP BY` で同時に出すことはできません。
    *   **手法A（CTE/サブクエリ）:** 分子用の表と分母用の表を別々に作ってから `JOIN` する。
    *   **手法B（ウィンドウ関数）:** `GROUP BY country, genre` で集約した結果に対し、`SUM(...) OVER(PARTITION BY country)` を使うことで、集約後の行を維持したまま「国全体の合計」を横に並べる。

---

### 3. 「各グループの最大値」を特定する定石パターン

**【言語化】**
「各Aの中で最もBなもの」という問題は、集計した後に「ランキング」または「自己結合」の工程が必要になる。

**【解説】**
*   **何が起きたか:** 「国ごとの最大売上ジャンル」を出すには、単に `MAX(売上)` を出すだけでなく、「その最大売上を持っているのはどのジャンル名か？」という紐付けが必要です。
*   **対策:** このパターンが来たら、以下の2ステップを脳内でイメージします。
    1.  **集計:** まず「国×ジャンル」の売上一覧を作る。
    2.  **抽出:** 
        *   `ROW_NUMBER()` や `RANK()` を使い、国ごとに売上順で連番を振って `WHERE rn = 1` で絞り込む（推奨）。
        *   または、`WHERE (country, sales) IN (SELECT country, MAX(sales) ...)` のように絞り込む。

### 次回以降に活かすための思考プロセス（チェックリスト）

クエリを書く前に、以下の3ステップを自分に問いかけてみてください。

1.  **「計算のベースになるのはどの行（粒度）か？」**
    *   売上計算なら、親の `total` ではなく、子の `price * quantity` を使う方が安全ではないか？
2.  **「分母と分子で集約のレベルが違わないか？」**
    *   「国×ジャンル（細かい）」と「国（粗い）」の比較なら、ウィンドウ関数か、別々のCTEが必要だと判断する。
3.  **「"各～の中で最大" という言葉が入っているか？」**
    *   入っているなら、最後に `ROW_NUMBER() OVER(...)` で 1位を抽出する構成にしよう、と決める。

**【まとめの一言】**
**「集計（GROUP BY）して、横に並べて（Window関数/JOIN）、最後に絞り込む（WHERE）」**
この3ステップを意識するだけで、今回のような複雑な集計問題の難易度は劇的に下がります。
